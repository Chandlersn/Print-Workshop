## 二、P0 · 必须修（安全边界，2 条）

### P0-1 存储层零路径校验 → 可删可读数据目录外的任意文件

**证据**（实测复现）

`electron/templates.cjs:121`：

```js
fs.unlinkSync(path.join(process.env.PRINTPRESS_DATA_DIR, t.background))
```

`electron/print.cjs` 的 `resolveSnapshot` / `deleteJob`：

```js
const abs = path.join(DATA_DIR, job.snapshot)
const jobDir = job.snapshot ? path.join(DATA_DIR, path.dirname(job.snapshot)) : null
// deleteJob 里：fs.rmSync(jobDir, { recursive: true, force: true })  ← 递归删整棵目录树
```

实测（数据目录 `root/data/`，受害文件 `root/victim.txt`）：

```
模板 background 设为 '../victim.txt' → deleteTemplate
  → root/victim.txt 删除后仍存在 = false     ← 被删穿
job.snapshot 设为 '../secret.txt' → resolveSnapshot
  → 返回了数据目录外文件的内容
```

**对比**：全项目唯一做 `..` 拦截的是 `main.cjs:47-50` 的 `pp://` 协议，且顺序正确（先解码后归一化）。存储层没有同等校验——协议层防住了，存储层没防住。

**影响**：`templates.json` / `print-jobs.json` 是用户可触达的文件（README 鼓励备份/迁库）。手工编辑一次即得任意文件删除/读取；配合 P1-2 的 `store:save` 可从渲染层无提权地做到。`deleteJob` 是 `rmSync(recursive)`，能删整棵目录。

**修法**：抽 `resolveInsideDataDir(rel)` —— `path.resolve` 后断言 `path.relative(DATA_DIR, abs)` 非绝对路径、不以 `..` 开头（Windows 另防盘符切换与 UNC），否则抛错。`background` / `snapshot` 均按受约束相对路径处理。

### P0-2 预览同源 + 模板属性未消毒 = 数据文件到 IPC 的完整链路

**证据**

`electron/render-engine.cjs:92-95`，字段样式属性裸拼进双引号属性：

```js
if (f.color) parts.push(`color:${f.color};`)        // 无任何校验
const fam = String(f.fontFamily).replace(/'/g, '').replace(/"/g, '')
```

`escapeHtml()` 只作用于**字段值**（`render-engine.cjs:213`），模板结构属性完全不经过它。

`color` 含 `"` 即可闭合 style 属性、注入任意 HTML 属性/标签。三个消费点：预览 iframe（`PrintCenterView.vue:534`，**无 sandbox**）、打印窗口、快照窗口。

**影响**：`templates.json` 里写一条 `color: 'red" onmouseover="..."'`，在打印中心预览该模板即触发。本地单机场景威胁面有限，但这是一条**无需用户交互、从数据文件直达 IPC 能力**的完整链路，属典型纵深防御缺口。

**修法**：`color` 走 `/^#[0-9a-f]{3,8}$/i` 白名单（渲染层本就是 `<input type="color">`，白名单完全够用）；`fontFamily` 改走 `escapeHtml`，去掉「剥引号」这种半消毒；`x`/`y`/`fontSize` 一并 `Number()` + 钳制。

## 三、P1 · 会产出错误结果（3 条，杀伤力最大）

### P1-1 「重打」丢弃原始行范围 —— 补打 3 人可能重打全部 100 人

**证据**

主进程完整保存了范围（`print.cjs:259`）：`selection: isPartial ? selection : null`  
历史表也渲染了范围（`PrintCenterView.vue:562`）：`部分 3/100`  
但 `reprint`（`PrintCenterView.vue:407-421`）只回填模板与数据集，**`job.selection` 从未被读取**，直接 `runAction()` → `buildPayload()` 取当前 UI 范围。

**两种错法**：此前未设过范围（`selRows === null`）→ 全量打 100 份；此前残留别的范围 → 打到另一批人。

**修法**：`reprint` 中若 `job.partial && Array.isArray(job.selection)`，先 `setScope(job.selection)` 再执行，并提示「按原任务范围重打 N 行」。

### P1-2 多联版式回退单页，全程静默

**证据**（实测）

`render-engine.cjs:174-178` 判定回退并给出 reason：

```
resolveLayout → {"enabled":false,"reason":"纸张 210×297mm 放不下 2 个 200×200mm 的成品"}
```

主进程把 reason 丢掉（`print.cjs:207-210`）：

```js
: { enabled: false },      // ← reason 未透传
```

前端三分支（`PrintCenterView.vue:513-517`）只区分 fold / grid / 单页，**回退后的 `{enabled:false}` 与真正的单页版式不可区分**。

实测：配了多联却放不下时，`layout = {"enabled":false}`，`pageCount = 2`（按单页出片），界面零提示。

**影响**：用户把纸张改小或成品改大后回打印中心，预览页数暴涨、导出版式与设计意图完全不符，且**没有任何线索**。模板工坊里有红字警告，但换页签后提示消失。

**修法**：`print.cjs` 透传 `{ enabled:false, mode, reason }`，前端补分支显式提示「当前纸张放不下，已按单页出片，请回模板工坊调整」。

### P1-3 打印失败零留痕 —— 用户以为打过了，实际一张没出

**证据**：`ipc.cjs:298-319` 的 `print:send` **完全没有 try/catch**，而结构对称的 `printExportPdf`（`ipc.cjs:259-295`）有完整 catch + `status:'failed'` 留痕。`printer.cjs:49-69` 的 `loadHtml` 在 3 次重试耗尽后 `throw`。

```
printer.sendToPrinter 抛错 → 冒泡出 ipc
→ createJob 那行永远不执行 → 历史一条都不留
```

**影响**：直接违反 `print.cjs:10` 自己声明的「无论范围大小，每一次出片都留痕」不变量。

**修法**：`print:send` 照 `exportPdf` 结构包 try/catch，catch 里 `createJob({status:'failed', detail})` 后再 rethrow。

## 七、审计中被证伪的 3 条怀疑（勿重复排查）


1. **「`saveTemplate` 会丢数据集」** —— 证伪。二分定位后确认是审计脚本自身错误：`buildBatchHtml` 签名是 `(datasetId, templateId, rows)` 三个位置参数，脚本按对象传导致 `datasetId` 变成 `"[object Object]"`。产品代码正常。
2. **「`importFromFile` 不落盘」** —— 证伪。xlsx 分支返回探测信息是 `inspectFile` 的正常行为（需用户选工作表），`importFromFile` 的 CSV 路径实测正常落盘。
3. **「`refreshAll` 无 catch 会导致 IPC 异常时整页空白」** —— 成立但降级为 P1（后果是显示层无提示，非数据损坏）。
