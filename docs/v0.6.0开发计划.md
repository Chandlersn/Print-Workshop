## 一、实施约定

- 以[图片变量与批量人像出片方案](图片变量与批量人像出片方案.md)为需求依据。
- 新占位框使用**工程格式 5**。格式 3 已用于仅编辑可见图层，格式 4 已用于渐变与阴影。
- 数据列保存相对文件名；照片导入后使用内容寻址的素材标识。名单不能触发任意路径或网络读取。
- 匹配使用 NFC、小写、去除 PNG/JPEG 扩展名后的相对名称；保留子目录。同键多文件必须报告冲突。
- **默认保留照片原始字节**。不把旧方案中的 JPEG 92 质量重编码作为默认行为；输出优化须以后提供明确选项。
- 变量照片通过外部资源引用加载，打印主动使用文件页面。归档采用 `snapshot.html` 加同目录 `photos/`，照片按内容去重复制；整个任务目录可以迁移并离线回看。
- 原图和绑定索引分开保存。索引只在导入完成后发布；中途失败不得覆盖上一次绑定。已入素材库的原件保留供复用。

## 三、首批验收标准

1. 普通名称、中文、大小写、NFC/NFD、JPG/JPEG、子目录均可正确匹配；同名不同格式不擅自取第一张。
2. 绝对路径、UNC、盘符、协议、控制字符、上级目录与符号链接不能成为照片来源。
3. 坏图、超限、缺图、空值、多行共用照片可区分，问题行号保持数据集原始行号。
4. 修改名单后重新计算匹配，不缓存旧行到照片的映射；切换数据集不能显示旧请求结果。
5. 导入不压缩原件。重复内容复用素材；重复导入替换该列的文件清单，避免旧目录条目混入。
6. 打印窗口实际解码外链原图，坏图阻断；归档照片与原件哈希相同，拷走任务目录后仍能回看。
7. 全量领域回归及前端构建通过。大作业、完整动态出片和实际安装包另行验收，不以首批测试代替。

## 四、后续实现要点

人像框保持既有图层顺序；不能把所有变量图片统一叠加到静态图层顶部。数据列绑定使用稳定的 `key`，展示使用别名，改别名不破坏绑定。

```js
// M2 已实现；静态图片仍必须提供 assetId。
const portrait = {
  id: 'portrait_1', type: 'image', variable: true, bindColumn: 'photo',
  x: 20, y: 30, w: 35, h: 45,
  fit: 'cover', focal: { x: 0.5, y: 0.5 }, radius: 0,
};
// schemaVersion = Math.max(既有版本, 含变量图片 ? 5 : 1)
```

大作业先测原图外链的峰值内存和输出体积，再决定分批页数与 PDF 合并方式；不能只用同一图片重复 500 次替代 500 张不同照片，也不能把降画质当作默认兜底。
