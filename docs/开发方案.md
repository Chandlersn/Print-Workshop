# 批印坊（PrintPress）开发方案

> 工作名「批印坊 / PrintPress」为占位名，可随时替换。
> 定稿日期：2026-09-30。源头项目：MediaArt-workbench 打印三件套（证书管理 / 模板管理 / 打印中心）。

---

## 1. 项目定位

**一句话**：本地离线的通用批量打印工具——导入一张数据表，上传一张底图，拖拽排版，一键批量打印或导出 PDF。

**范围界定**：前提是用户已持有**经审核的数据集**与模板。本工具只负责「**快速简单地做好模板** + **批量化出片**」及其细节补充；数据集管理面（重命名 / 复制 / 导出 CSV）不属于本工具职责，留在用户自己的表格里完成。

**目标用户**：先做给自己和身边人用（行政、教务、活动组织者、小微商家）；产品化顺其自然，不作为抢市场项目。

**典型场景**：证书、奖状、结业证、工牌、参会牌、邀请函、标签、价签、准考证、简易快递面单。

**竞品格局（2026-09-30 实查）**：

| 类型 | 代表产品 | 观察 |
|---|---|---|
| 国产证书批量打印 | 贵鹤证件精灵、绿精灵、飚风 v5.36、贵鹤助手 | 模式与我们设想一致：模板+数据分离、Excel/CSV 导入、拖拽排版、批量 PDF/打印、VIP 授权（贵鹤验证了商业模式）。但 UI 停留在上个时代、下载站分发、信任度低 |
| 专业标签/证卡 | BarTender、NiceLabel、CardPresso | 功能强但贵、面向物流/制造业，普通用户用不上 |
| 在线工具 | Canva、各类在线证书生成器 | 隐私顾虑、水印/张数限制 |
| 古典方案 | Word 邮件合并、LibreOffice | 门槛高、体验差 |

**结论**：需求已被市场验证（不是赌需求），但纯功能层面无先发优势。差异化打法是**体验与信任**——现代审美（宣纸墨韵）、干净离线（数据不出本机、无捆绑）、过程透明（打印历史回溯/归档/出口校验，竞品普遍没做或很糙）。竞品反而是免费的老师：贵鹤的 `{{列名}}` 变量绑定、.gzjt 模板包分发、数据存 %APPDATA% 的做法值得 M1/M2 设计借鉴。

**能力渊源**：核心能力已在 MediaArt-workbench 打印三件套中验证跑通（数据驱动字段目录、拖拽吸附排版、打印前出口校验、留痕归档），本项目将其从「证书」垂直场景解耦为通用引擎，并按产品级标准重建。

## 2. 第一性原理分解

```
批量打印 = 数据集 × 模板 × 渲染引擎 × 输出通道
```

| 要素 | 含义 | 对应子系统 |
|---|---|---|
| 数据集 | 用户导入的任意表格（Excel/CSV），字段从真实数据派生 | 数据页 |
| 模板 | 底图 + 字段框（位置/字体/颜色/对齐），用户自排版 | 模板工坊 |
| 渲染引擎 | 模板 × 每行记录 → 一页 HTML → PDF/打印 | 引擎层 |
| 输出通道 | 打印机 / PDF 导出 / 归档留痕 / （远期）面单对接 | 打印中心 |

设计公理：**引擎不知道"证书"是什么**。它只知道「一组列 × 一组行 × 一个模板」。证书只是数据集的一种实例。

## 3. 技术选型

### 3.1 选型结论

**Electron + Vue3 + Vite + 纯 Node 主进程（无 Python）**。

### 3.2 理由

| 维度 | 纯 Node（选定） | Electron + Python sidecar |
|---|---|---|
| 打包 | 单运行时，NSIS 安装包约 80~100MB | 双运行时，PyInstaller sidecar，体积与故障面翻倍 |
| 打印通道 | Electron 原生 `webContents.print` / `printToPDF`，零依赖 | 需经 HTTP 桥接绕一圈 |
| 维护 | 一门语言一套栈 | 两套运行时、两份依赖清单 |
| 团队既有经验 | Vue3 + Vite + Electron 已熟练 | Python http.server 模式来自内部项目，产品化无优势 |

### 3.3 关键库选择

| 用途 | 选择 | 说明 |
|---|---|---|
| Excel 解析 | `exceljs`（或 SheetJS `xlsx`） | M1 时实测定稿 |
| CSV 解析 | 自研轻量解析 + 多编码检测（UTF-8 / GBK） | 沿用「无重依赖」思路 |
| 存储 | `data/*.json` 原子写（写临时文件 + rename） | 沿用 dataStore 模式；**实测 5 万行仍线性可用**（见 `docs/存储性能基准.md`），阈值放宽到 10 万行 / 20MB |
| 打包 | `electron-builder` → NSIS 安装包 | M5 |
| 自动更新 | `electron-updater` | 只留接口位，不提前实现 |
| 原生模块 | **零原生依赖**原则 | 避免 Electron 重编译噩梦；better-sqlite3 因此不选 |

## 4. 总体架构

```
┌─ Electron 主进程（Node）────────────────────────┐
│  ipc-gateway        统一 IPC channel 路由         │
│  dataStore          datasets / templates / jobs / │
│                     settings，JSON 原子写          │
│  importer           xlsx / csv → dataset          │
│  field-catalog      字段目录派生 + 分层过滤规则     │
│  render-engine      模板 × 记录 → HTML            │
│  print-channel      printToPDF / webContents.print│
│  archive            打印留痕 + PDF 归档目录         │
│  font-detector      系统字体检测（Windows 注册表优先）│
└──────────────┬──────────────────────────────────┘
               │ IPC（contextBridge 白名单暴露）
┌──────────────┴──────────────────────────────────┐
│  渲染进程（Vue3 + Vite，宣纸墨韵主题）              │
│  数据页    导入 → 预览 → 字段清单（含填充率）        │
│  模板工坊  底图上传 / 画布拖拽 / 吸附 / 多选 / 撤销   │
│  打印中心  批量发起 / 出口校验 / 历史 / 归档回看      │
│  设置与示例库                                        │
└─────────────────────────────────────────────────┘
```

**与源项目的关系**：本项目独立演进，不共享运行时代码；引擎逻辑以「移植 + 对拍」方式从 workbench 迁移（见第 7 节），移植后以新项目为准，workbench 证书打印保持现状不动。

## 5. 数据模型（data/*.json）

```jsonc
// data/datasets.json
{
  "id": "ds_xxx",
  "name": "比赛证书名单",
  "source": { "type": "xlsx", "fileName": "名单.xlsx", "importedAt": "..." },
  "columns": [
    { "key": "name",  "label": "姓名", "alias": "姓名", "type": "text" }
  ],
  "rows": [ { "name": "张三", "award": "金奖" } ],
  "stats": { "rowCount": 120, "columnFill": { "name": "120/120" } }
}

// data/templates.json
{
  "id": "tpl_xxx",
  "name": "金奖证书",
  "pageSize": { "w": 297, "h": 210, "orientation": "landscape" },
  "background": "assets/bg/xxx.png",          // 应用数据目录内相对路径
  "fields": [
    { "key": "name", "x": 0.5, "y": 0.62, "fontSize": 28,
      "color": "#8b0000", "align": "center", "bold": true,
      "fontFamily": "KaiTi" }
  ],
  "createdAt": "...", "updatedAt": "..."
}

// data/print_jobs.json
{
  "id": "job_xxx",
  "templateId": "tpl_xxx", "datasetId": "ds_xxx",
  "refKeys": ["张三", "李四"],                // 主键列取值，用于回溯
  "count": 120, "channel": "printer|pdf",
  "status": "done|failed",
  "snapshotPaths": ["archive/2026-09/xxx_张三.pdf"],
  "createdAt": "..."
}
```

要点：
- 位置一律存**画布百分比**，纸张尺寸变化时排版自适应（沿用源项目经验）。
- 列的 `key` 为规范化名，`alias` 为用户可见名（用户可改名，替代源项目写死的 `CERT_FIELD_LABELS`）。
- 快照 PDF 按月分目录存应用数据目录，`print_jobs` 只存相对路径（沿用源项目 `_resolve_snapshot` 新旧兼容思路）。
- **状态回写规则（不变量）**：`print_jobs` 记录每一次出片（含部分出片，携带 `rows` / 范围字段）；但数据集级 `printCount` / `printed` 状态**只由全量出片回写**，部分出片（行级勾选 / 分组导出）不回写——避免「打了 3 个人却显示整份已打」。判定用「行数覆盖」，不逐行持久化状态。

## 6. IPC 接口清单（MVP）

| Channel | 方向 | 说明 |
|---|---|---|
| `dataset:import` | R→M | 导入 xlsx/csv，返回 dataset 概要（列名 + 前若干行预览） |
| `dataset:list` / `dataset:get` / `dataset:delete` | R→M | 数据集管理 |
| `dataset:renameColumn` | R→M | 列别名修改（写回 alias） |
| `template:crud` | R→M | 模板增删改查（全量快照写） |
| `template:uploadBackground` | R→M | 底图上传，返回尺寸 + 建议纸张 |
| `font:list` / `font:upload` / `font:delete` | R→M | 字体管理（删除前校验是否被模板引用） |
| `catalog:fields` | R→M | 当前数据集字段目录（含 fill 填充率、可打印过滤） |
| `print:generate` | R→M | 模板 × 选中行 → HTML → 打印/PDF |
| `print:validate` | R→M | 出口校验：返回空值明细（前端弹确认框，可中断可放行） |
| `job:list` / `job:openSnapshot` | R→M | 留痕查询 + 归档件回看 |

安全约定：contextBridge 只暴露白名单 channel；所有文件读写限制在应用数据目录内；路径归一化前先拦 `..`（源项目穿越防护教训直接继承）。

## 7. 引擎移植清单（workbench → 本项目）

| 源实现（server/print/routes.py + 前端） | 移植为 | 备注 |
|---|---|---|
| `cert_field_catalog`（从真实记录键并集派生 + fill 填充率） | `field-catalog.js` | 数据源参数化：certificates → 任意 dataset |
| `_printable_key` 分层过滤（黑名单→命名语义→值形态→长度） | `field-catalog.js` 内规则 | 字面量集合须先用真实数据校准（源项目教训） |
| `CERT_FIELD_LABELS` / `CERT_INTERNAL_KEYS` 写死元数据 | 列 `alias`（用户可改）+ 数据集级内部列标记 | 去证书语义 |
| `build_html`（模板渲染 + @font-face 注入 + 转义） | `render-engine.js` | 输出与源项目对拍 |
| `_detect_system_fonts`（Windows 注册表优先 + 目录兜底） | `font-detector.js` | 候选清单 + 存在性检测，不写死暴露结果 |
| 画布吸附对齐 / 多选对齐 / 撤销重做 / 键盘微调 | `TemplateCanvas.vue` | 交互参数照搬（吸附阈值 6px、快照栈 50 条等） |
| 打印前出口校验（空值弹窗、可中断可放行） | 打印中心 | 硬中断会卡死合法全空字段——保留「仍要打印」放行 |
| `_record_value` 列名兼容三存法 | 数据层统一 `getColumnValue` | 新项目从第一天就用单一转换函数 |

**对拍验证**：M3 用同一份测试数据 + 同一模板，比对源项目 HTML 输出与本引擎输出（字段取值、坐标换算、字体注入），确保移植无行为漂移。

## 8. UI 与交互规范

- **主题**：宣纸墨韵（米白底 / 墨黑字 / 朱砂红点缀），token 对应 `--paper / --line / --cinnabar / --stone`；暗色模式为必验项。
- **零 emoji**：全部用纯文字标签。
- **语义类**：内层板块统一语义类名，禁内联样式、禁裸 div 堆砌（沿用源项目前端纪律）。
- **统一组件**：下拉一律用 CustomSelect（带分组支持），新建页面不得引入原生 `<select>`。
- **交互理念**：入口宽松（导入不做校验）、过程透明（无数据字段半透明 + 填充率徽标）、出口把关（打印前空值弹窗）。

## 9. 产品化底座（Phase 3）

- **安装即用**：electron-builder NSIS 安装包，装完即可跑，无环境依赖。
- **示例模板库**：内置 3~5 套模板（证书/工牌/邀请函/标签）+ 示例数据，首次启动引导「用示例走通全流程」。
- **更新机制**：electron-updater 接口位先留好（版本号上报 + 检查更新空实现），有分发渠道后再接真源。
- **授权/账号**：**本期不做**，仅在 settings 预留字段位。离线单机产品先验证价值。
- **快递面单**：作为「又一类模板」支持（圆形单排版），**电子面单 API 对接（菜鸟/快递100，需服务商资质）放远期，本期不做**。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| JS 移植与源 Python 引擎行为漂移 | 同数据同模板对拍（第 7 节）；差异即 bug |
| 用户 Excel 千奇百怪（合并单元格/多级表头/乱码） | 入口宽松：能读多少读多少 + 预览确认页；出口校验兜底 |
| 双项目（workbench / new-tools）各自演进产生认知漂移 | 本文档为唯一权威；workbench 打印模块冻结不再加功能 |
| 打包体积 / 签名 / 杀软误报 | M1 结束就先出一个安装包冒烟，不留到最后 |
| 数据量超预期 | 已实测（`docs/存储性能基准.md`）：5 万行导入 158ms、改一格 113ms，线性可用。**触发条件校准为 > 10 万行或 datasets.json > 20MB**；届时优先改「整文件重写」写路径（分文件/追加式），而非引入原生模块——SQLite 会破坏本项目的「零原生依赖」原则 |

---

## 11. 明确不做（本期边界）

- 数据集管理面（重命名 / 复制 / 导出 CSV）——数据集由用户准备且已审核
- 电子面单运营商 API 对接
- 云端同步 / 多设备
- 账号体系与授权收费
- 模板在线市场
- 复杂表格公式 / 数据清洗 DSL
