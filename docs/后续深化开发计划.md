# 批印坊后续深化开发计划

> 建立：2026-11-15；同日依据当前工作区代码、使用说明、测试和已有验收报告重新核查。计划用于以后选题和跟踪，不代表发布日期或版本承诺。
>
> 基线：`package.json` 为 v0.7.2；单人海报复用、删除及「使用中」高亮等近期修改在当前工作区，是否已提交、打包或发布以实际状态为准。本文的“已实现”指核查到相应代码及功能入口，不等同于本次重新运行全部测试或实际打印机验收通过。

## 产品方向

继续围绕“名单 → 照片 → 模板 → 检查 → 打印或导出”，减少用户重复操作。前端优先呈现主要动作、必要结果和明确的下一步；后台承担引用判断、任务编排与恢复等复杂工作。保持现有本地离线制作方式。

**避免重复建设：**先确认已有功能和使用反馈；把“需要补充验证”“局部体验改进”“尚未实现”分开记录。本文不是要求重新实现下列已有功能。

## 后续工作：按必要性排序

### P0：完整备份与恢复设计

现有数据目录迁移和工程包已经解决一部分转移需求；待评估的是**整个工作环境**的可验证备份与恢复，而不是重新制作目录迁移或工程包。

- [x] 对照实际存储位置，核清名单、照片、模板、底图版本、字体、素材库、照片处理结果、打印历史、配置和独立 `PRINTPRESS_ASSET_DIR` 的备份边界，见[完整备份与恢复方案](./完整备份与恢复方案.md)。
- [x] 设计备份内容与空间提示、完整性校验、版本兼容和目标目录冲突处理；方案采用新目录隔离试恢复后由用户选择切换。具体实现与验证尚未完成。
- [ ] 用跨目录、跨机器模拟数据和外置素材目录做恢复演练，核对人员照片、单人海报、模板和历史快照。
- [ ] 仅在用户确有需求时，单独设计删除后的回收与恢复；不得把工程底层保留版本说成已完成通用回收站。

验收以备份可实际恢复并重新打开、预览和输出为准；中断、损坏、缺少外置目录及空间不足时需明确提示。

### P1：出片前问题处理的缺口验证

当前已有预检、问题列表、定位记录、单张照片精修返回打印预览及重新加载预检。待做的是核查**问题列表入口**能否更顺畅地到达合适的修复方式，而不是从零开发预检。

- [x] 在隔离数据的真实 Electron 界面中走查缺图：从问题列表进入照片库，补图后返回同一模板及人员所在页并重新预检；补图确认阶段禁止通过返回按钮离开。测试见 [photo-e2e.cjs](../test/photo-e2e.cjs)。
- [ ] 分别走查冲突/坏图、裁切和低清晰度：确认现有跳转与修复入口是否足够；仅对确有断点的路径补充快捷入口或返回状态。
- [ ] 回归多联、对折、部分打印、共享原图和单人例外；保留现有阻断与留白语义。

### P1：照片效果与任务体验验证

- [ ] 用轻度发虚、小尺寸、噪点、压缩痕迹及透明人像边缘等真实样张验证现有锐化；对比原图、处理图和纸面效果，必要时再调整默认强度。
- [ ] 核验已有进度、取消、失败提示、自动重试及缓存复用在大批量和中断后的表现；如果用户无法快速找到具体失败人员，再设计更直接的失败列表或定向重试。
- [ ] 用真实照片验证预览与批量抠图模式不同时的实际差异，确认已有提示是否足够；按反馈优化，不重做现有模式选择。
- [ ] 回归已有单人例外筛选、编辑和恢复统一样板，尤其验证共享原图及更换照片后的行为。

### P1：后台素材整理继续分期

复用已有「素材整理」入口、盘点和安全清理能力。细则以[后台重复素材管理方案](./后台重复素材管理方案.md)为准。

- [ ] 核查未保存草稿、历史快照内嵌图片及其他引用来源；先用真实数据做只读模拟，不把“未发现已知引用”视为可删除。
- [ ] 逐类验证其他明确可再生缓存和已结束任务残留；保留实际释放、跳过与失败统计。
- [ ] 原件自动回收前，设计并验证观察期、隔离恢复、崩溃日志、并发协调与删除前复核，并审查 I-32；当前不扩大原件自动删除范围。
- [ ] 单独验证跨池副本的读取、生命周期和备份语义；视觉相似或文件名相同不能证明可以合并。

保护用户主动导入的素材、名单照片、已保存工程、单人修改和历史输出；数据不完整或无法确认时跳过清理。

### P2：真实打印与现有补打能力验收

- [ ] 在目标设备上验证打印机、驱动、纸张、方向、双面、多联及取消行为；记录机型、驱动、操作和结果。
- [ ] 对已有“已提交批数”提示和按稳定 ID 补打进行用户场景回归，明确哪些范围可以可靠识别；系统队列状态不可等同于纸张已打印完成。
- [ ] 基于当前版本重测必要的大名单和大图片场景，记录内存、耗时与任务中数据变化；保留 S1 既有 500 张验收结论，不重复声称从未测试。

### P2：模板复用中尚未覆盖的需求

- [ ] 调研现有字段 key 换绑和缺失字段提示是否已足够。只有确有需要时，才设计不同字段名称之间的显式映射及用户确认。
- [ ] 检查换绑后变量照片列、已保存照片规则和单人例外的实际行为及提示，避免误以为规则会自动应用到新名单。
- [ ] 根据真实业务补充少量可编辑、尺寸明确的示例模板；不把已有证书、胸牌或桌牌能力列为全新功能。

### P2/P3：分发和探索

- [ ] 按分发需求评估 Windows 代码签名、离线安装和升级失败恢复；版本信标、安装包和实际 Release 的状态要一致。
- [ ] 如用户样张显示现有锐化确实不足，再评估本地 AI 超分辨率的效果、CPU 耗时、内存、包体和模型许可，明确其可能生成不准确细节。
- [ ] 云同步、多人协作和更复杂的专业排版先收集真实需求，不默认纳入近期版本。

后续开始工作前，先核对代码、用户反馈、Git 状态和相关测试；完成后记录具体实现、测试及仍未覆盖的情况，再调整本文状态。
