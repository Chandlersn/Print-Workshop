# S1 分批出片验收报告

> 日期：2026-10-12。程序：本地预览版 0.6.0-alpha.9。

分批照片加载、PDF 合并等待、测试链、任务进度与取消、逐页预览已经修复并接通。实际打包程序连续完成两轮 500 张不同大原图的 PDF 导出，每轮均为 500 页；采样内存峰值 2,034,708,480 字节，低于原计划 4 GB 目标。

## 验证环境与方法

- 使用 Windows 本机的实际 `release-060-preview9/win-unpacked/批印坊.exe`，通过本地调试协议调用包内预加载能力，执行真实导出 API、媒体会话、打印通道和合并器，没有替换打印后端。
- 数据目录与用户目录均隔离；使用 S1 基准测试已有的 500 张合成 JPEG，500 个不同 SHA-256，合计 1,871,428,759 字节。
- 预建隔离名单和素材索引，原件通过硬链接引用既有夹具。本轮重点为新程序的预览、分批导出和归档；500 张导入的测量沿用基准报告，未重新操作本轮安装包的文件夹选择对话框。
- 照片作业默认每批 25 条，共 20 批；每批使用独立会话，并为该会话注册受控媒体处理器。
- 通过 Windows 进程查询每 2 秒采样新启动的应用进程 Working Set，排除启动前已存在的同名程序；该值为采样峰值，不是连续测量的瞬时最高值。
- 同一程序进程连续执行两轮，第二轮原子替换同一最终 PDF，检查重复执行与已有文件处理。
- 完成后核对最终页数、临时文件、成功历史，以及两轮归档共 1000 个原件的 SHA-256。

原始结果：`.workbuddy-ai/tmp/s1-shipped-kmpuZI/result.json`。验收驱动：`.workbuddy-ai/tmp/verify-s1-shipped.cjs`。

## 修复内容

1. 独立分批会话不会继承默认会话的媒体处理器，现已为实际会话分别注册。
2. 异步 PDF 合并必须等待完成，现已补上 `await`，页数检查和临时件清理在合并结束后执行。
3. 新增缺失的编排测试，恢复完整测试链；失败与取消分别留痕。
4. 预览按物理纸张取记录，导出使用完整选择范围；多联批次保持整纸边界。
5. 进度按任务键关联，分批取消在批次边界生效，已有最终文件不会被失败半成品覆盖。
6. 分批期间名单、模板或照片绑定变更时停止后续批次，防止混用前后内容。
7. 非静默直接打印每批确认设备和设置，避免后续批次自动切换到默认打印机。

## 后续验收与限制

- 大原图 PDF 仍较大：本测试 1.87 GB 原件生成约 7.90 GB PDF。Chromium 会对部分大图重新编码，其行为与原基准一致；合并器保持各批 PDF 资源，不再栅格化页面。本轮未新增压缩原件或缩略图出片策略。
- 原件与归档的字节保真已经核对；大图在 PDF 中的编码、尺寸及像素保真需继续专门验证，不能把归档哈希一致视为 PDF 原始 JPEG 码流完全保留。
- 系统打印机的设备选择、实际纸张和取消仍需设备验收；本轮真实输出验证使用 PDF，打印队列行为通过注入后端测试。
- 0.5 升级、数据迁移、S2 导入暂存、S3 增量补图及 S4 完整补打属于后续阶段。正式 0.6 尚未发布，整套任务迁移继续暂缓。
