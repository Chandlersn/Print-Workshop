# 名单筛选与打印历史删除核查

日期：2026-10-12。本轮是 v0.6 本地预览增补，不代表 S2—S7 已实现或正式版已发布。

## 一、数据页筛选

在侧栏导入批次下方新增「全部／已打／未打」，筛选单位为整份名单，而非名单中的人员行。

- 使用名单持久化的 `printCount`；成功全量直接打印或导出 PDF 后增加，部分补打、失败和取消不增加。
- 只筛选当前导入批次，与名称搜索叠加；计数反映当前批次和搜索条件。
- 筛选、搜索和切换批次后，详情跟随可见名单；空结果隐藏详情，避免编辑被筛掉的名单。
- 切换批次保留状态筛选，新导入回到「全部」并清空搜索。补录跳转会展开筛选以显示目标。
- 删除打印历史不撤销实际出片，名单累计已打状态保留。打印中心统计来自当前保留的历史，两者口径不同，说明已同步。

## 二、点击删除后释放哪些数据

| 数据 | 删除后的结果 |
| --- | --- |
| `print-jobs.json` 的该任务条目 | 移除全部同 ID 条目，其他记录保留 |
| `print-jobs.json.bak` 恢复副本 | 同步为删除后的内容，正常完成时不会恢复出已删任务；更新失败单独提示 |
| `archive/年-月/任务ID/snapshot.html` | 删除，HTML 中内置底图和字体也随文件释放 |
| 同任务目录的 `photos/` | 删除归档照片副本及该任务目录内其他文件 |
| 已为空的月份目录 | 尝试移除；含其他任务或文件时保留 |
| 取消记录（无快照） | 仅移除任务条目、同步恢复副本 |
| 用户保存的 PDF | 保留；不会根据历史 `detail` 路径去删除文件 |
| `design-assets/`、`design-thumbnails/`、素材库索引 | 保留，都是共享原件或缓存，不属于任务归档副本 |
| 名单、照片匹配绑定、模板、底图工程、上传字体 | 保留 |
| 名单 `printCount`、`lastPrintedAt` 等累计状态 | 保留，因此该名单仍可能出现在「已打」 |
| Chromium 缓存、操作系统打印队列 | 此操作不清理 |

此前两个缺陷已修复：归档删除失败仍移除元数据并提示成功；快照路径仅限制在 data 内，未限制归档目录属于该任务。另补上删除后恢复副本同步，避免损坏恢复时复活已删条目。

## 三、失败处理与目录保护

- 删除前校验全部同 ID 记录的路径，必须是 `archive/合法月份/该任务ID/snapshot.html`。
- 拒绝其他任务目录、共享素材目录、非法月份、路径穿越及归档父目录/任务目录的符号链接或 junction。
- 归档不存在视为已清理；文件占用等清理错误会保留历史记录并报错，用户可重试。
- 清理文件后才移除元数据。若元数据写入失败，记录仍可保留或由存储备份恢复；重试可接受归档已不存在。目录清理与 JSON 写入并非跨文件系统事务。
- 恢复副本更新失败时，主记录及归档可能已删除，界面会明确指出副本未更新，不能假报全部清理完毕。

## 五、尚未覆盖的历史残留

当前历史索引最多保留最近 200 条；旧逻辑自动截断索引时不删除更早的归档目录。早期已因清理失败丢失索引的目录也可能残留。本轮删除只清理用户指定任务，**不会扫描或批量删除这些无索引归档**。此类残留纳入后续 S7 引用检查与资源管理处理，避免未经核对误删。

本轮也未新增增量补图、单人裁切或整套任务迁移。
