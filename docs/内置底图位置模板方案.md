# 内置底图位置模板方案

> 编写日期：2026-10-09（v4，S1/S2/S3/S4 已实现）。基线 v0.4.0（底图图层工程 + 模板文本变量）。
> 状态：**S1 领域层、S2 编辑器、S3 模板库、S4 脱离系统打印已完成**；S5 出片验证待做（需真实安装包）。
> **范围变更（二次收敛）**：内置清单从 7 套再收敛为 **1 套**——只留 A1 身份证正反面复印件；
> 票据粘贴单与 5 套手写练习纸全部移除。同时「常用模板」下拉从「一屏内置常量」改为
> **「内置模板（身份证）+ 最近使用（自动记录用户习惯）」**。原因见 §2 与 §4。
> （第一次收敛：原清单 10 套 → 7 套——A2 银行卡/社保卡、A3 护照+身份证、A5 A4 九宫格照片明确不做。）
> 关联：[底图制作使用说明](底图制作使用说明.md)、[底图图层编辑开发方案](底图图层编辑开发方案.md)、[v0.5.0 开发计划](v0.5.0开发计划.md)。

## 一、要解决什么

**诉求**：内置一批「已经排好位置」的常用底图，用户选一个就能往固定位置放图，不必自己量尺寸、摆框、对位置。典型例子是 **A4 纸上的身份证正反面复印件**——两张卡的标准尺寸是 85.6 × 54 mm，手工摆很容易大小不对、上下歪、间距不均，而这类复印件是办事刚需。

**收敛后的路线（本次讨论结论）**：

1. **只做参考框**：内置模板里放**虚线参考框 + 尺寸标注**，用户自己把图片拖进去对齐。**不做**「点框自动填图」的槽机制（记为后续可选，见 §6）。
2. **内置 1 套证件类（身份证正反面复印件）**（清单见 §2）。
3. **导出后能脱离本系统打印**：导出 PNG 成功后提供「打开所在文件夹 / 用系统程序打开」，用户拿着图片在系统看图器或打印店就能印。

## 二、内置清单（最终 1 套）

| # | 模板 | 版面 | 参考框与尺寸 | 尺寸依据与可靠度 |
| - | --- | --- | --- | --- |
| A1 | **身份证正反面复印件** | A4 竖 | 2 框：85.6 × 54 | ISO/IEC 7810 **ID-1**，国际标准，**高** |

A1 的全部图层（参考框 + 尺寸标注 + 说明）都标 `editorOnly: true`：**编辑器里看得见，出片一个都不出现**。

> **二次收敛（2026-10-09）删掉了什么、为什么**：
> - **票据粘贴单**：尺寸本就是自定义（180 × 40），没有任何「量不出来的标准」可省，用户自己拖两个矩形即可。
> - **5 套手写练习纸**（田字格 / 四线三格 / 横线稿纸 / 方格纸 / 五线谱）：它们不帮用户「对齐图片」，
>   只是替用户画格线，而格线用「＋矩形」自己就能画。
> - **真正的原因**是第二条：内置预设越多，工程库越容易被堆满——「常用模板」下拉每选一次就落库
>   一份**新工程**，用户为了挑顺眼的版面点几遍，工程库里就多出一堆同名工程（**实测一次会话堆出 18 个**）。
>   所以内置数量必须克制，把下拉让给「最近使用」（用户自己真正在用的工程），而不是一屏内置常量。
>
> ⚠️ 若日后重新加回格线类预设，务必记住两类预设的性质**相反**：格线是普通图层、**就是要印出来的**，
> 标成 `editorOnly` 会得到一张白纸（同样不报错）。`test/design-presets.cjs` 里保留了这条提醒。

> **明确不做**（原清单中的三项，2026-10-09 收敛）：
> - **A2 银行卡 / 社保卡正反面**：与 A1 同为 ID-1 尺寸，做出来是 A1 的换名字版本，不新增价值。
> - **A3 护照资料页 + 身份证**：组合版式（左右并排 vs 上下）无定论，先不做。
> - **A5 A4 九宫格照片**：用现有「多联/拼版」模式已能实现，不必内置。
>
> **不重复内置**：同一张照片重复 N 份（1 寸 8 张、2 寸 4 张）用现有「多联/拼版」模式已经能做，尺寸预设也有（`ITEM_SIZES`：1 寸 25×35、2 寸 35×49、5R 89×127…）。
>
> **把握不足、暂不内置**：户口本（约 143×105）、驾驶证（约 88×60）、毕业证（约 185×260）、结婚证（约 128×90）、营业执照——各版式差异大，内置一个「可能不对」的尺寸比不内置更糟。真要做，需先在真实证件上量过再定。

> **两处「只有看渲染图才会发现」的坑**（相关预设已随二次收敛移除，教训保留）：
> - 四线三格若「行高 = 行内线距」且行首尾相接，整页会退化成均匀横线，用户看不出「一行」在哪。
> - 票据粘贴单若行距只比框高大 5 mm，尺寸标注会**压在上一行框的下边上**。
>
> 两条都是**测试测不出来、只有把预设渲染成 PNG 逐张看才能发现**的缺陷——所以「渲染成图逐张肉眼核对」
> 是这套预设的必备验收动作，不要只靠断言。

## 三、唯一的新机制：`editorOnly`（仅编辑可见）

**为什么必须有**：参考框如果印出来，身份证复印件上就会多出一堆虚线；但如果只是隐藏（现有 `visible: false`），编辑器里也看不见，等于没有。现有能力里没有「编辑器看得见、出片看不见」这一档——**参考线**有这个性质（`使用说明:27`「参考线、选中框和操作手柄都不会出现在 PNG 或 PDF 中」），但参考线只是 x/y 直线，做不出矩形框和尺寸标注。

**做法**：给图层加一个布尔标记，`renderDesign` 按调用方决定要不要渲染它。

```js
// 已实现：图层级字段（design-layout.cjs normalizeDesign）
editorOnly: false,   // true = 只在编辑器里可见，打印与 PNG 导出都不出现
```

```js
// 已实现：renderDesign 增加选项
renderDesign(input, { includeEditorOnly = false })   // 默认不渲染（出片/导出天然正确）
```

- **编辑器**：`DesignSurface.vue` 传 `includeEditorOnly: true` → 画布上看得见、能选中、能拖动、能改尺寸。
- **出片 / 导出 PNG / 归档快照**：不传 → 自动排除，**不需要在每个出口各写一次过滤**（默认安全）。
- **图层列表 / 属性面板**：照常显示，并给一个「仅编辑可见（不打印）」勾选框，用户随时能改。
- 选中/拖动/吸附**完全复用现有逻辑**：命中框（`data-canvas-layer-id`）是按 `design.layers.filter(visible)` 生成的，`editorOnly` 图层照旧有命中框，拖动时**现有的图层边缘吸附**（`snapDelta` 会把其他图层的左边/中心/右边都当吸附目标）会自动把用户拖进来的图片对齐到参考框边缘。

### 3.1 格式版本必须升到 3（方案初稿在这里判错了）

初稿写的是「不动 schema 版本号，旧应用忽略未知字段、安全降级」。**这个判断是错的，而且错在危险的一侧**：旧应用（0.3.x）的 `normalizeDesign` 按固定字段表重建图层，未知字段不是被忽略而是被**剥掉**；剥掉 `editorOnly` 之后，参考框就退回成普通矩形图层，**正好会被印到身份证复印件上**，再存一次则永久丢失标记。

仓库里对这种情况已有成文约定（`design-layout.cjs`）：

> Older readers must refuse the new metadata instead of stripping it during a save.

即：**新元数据必须让旧读者明确拒绝，而不是静默剥掉**。所以：

- 图层带 `editorOnly: true` 时 `schemaVersion` 取 `Math.max(版本, 3)`；
- 旧应用打开会明确报「不支持的底图工程版本」——**宁可拒绝打开，也不静默印出参考框**；
- 顺带修掉一个既有隐患：原实现遇到分组/参考线时**直接赋值** `schemaVersion = 2`，会把「已是更高格式 + 恰好有分组」的工程倒标成旧格式，等于亲手开了静默降级的口子。现改为对每个特性取最大值。

版本 3 原本被 `docs/v0.5.0开发计划.md` 预留给渐变/阴影效果（尚未实现），已同步把那份计划改成「效果校验使用格式版本 4」。

改动面：领域层一个 `bool` 归一化 + 一个渲染选项 + 版本号取最大值，Vue 侧传一个参数、加一个勾选框。


## 四、交付入口（已实现）

底图编辑器「新建底图」旁是 **「常用模板」下拉**（`data-testid="design-preset"`），分两组：

| 组 | 条目 | 选中后 |
| --- | --- | --- |
| 内置模板 | 身份证正反面复印件（**唯一一套**） | **新建**：复制出一份新工程并落库（预设本身是常量，改坏了不影响它） |
| 最近使用 | 用户打开 / 保存过的工程，按最近使用倒序，最多 8 个 | **打开那份工程本身**，绝不复制 |

> 为什么第二组必须是「打开」而不是「新建」：早先下拉里全是内置常量、每选一次就落库一份新工程，
> 用户挑几遍版面，工程库就堆出一堆同名工程（实测 18 个）。「最近使用」若也走复制，
> 等于把同一个坑换个地方再挖一遍——所以 e2e 里正面钉住「打开前后工程总数不变」。

下拉的值自带前缀，界面据此分派（`<optgroup>` 只负责视觉分组，值本身必须能自解释）：
`preset:<id>` → 新建；`design:<id>` → 打开。

```js
// 已实现 electron/design-presets.cjs —— 纯 Node、零 electron 依赖，可单测
const PRESETS = [
  { id: 'id-card-a4', name: '身份证正反面复印件', summary: 'A4 竖版 · 上下两个 85.6 × 54 mm 标准卡位（ISO/IEC 7810 ID-1）', build },
]
module.exports = { listPresets, buildPreset, PRESETS }
```

接口沿用现有注册表约定（`electron/api.cjs`）：

```js
'design:listPresets':      { params: {},                              run: () => listPresets() },
'design:createFromPreset': { write: true, params: { presetId, name }, run: (p) => designs.saveDesign(buildPreset(p.presetId, p.name)) },
'design:touch':            { write: true, params: { id },             run: (p) => designs.touchDesign(p.id) },  // 记一次「使用」
```

`preload.cjs` 对应暴露 `listDesignPresets()` / `createDesignFromPreset(presetId, name)` / `touchDesign(id)`。

- 预设一律**过一遍 `normalizeDesign`** 再落库，保证模板不会漂移；`buildPreset` 的每个预设各自持有一份自增 `L1…` 图层 id（可复现，且多次构建互不干扰）。
- **下拉选完自动复位**（`pickPreset` 把 `event.target.value` 置空）：否则再选同一项不会触发 `change`，用户会以为「点了没反应」。
- 预设 id 有误时 `buildPreset` 直接抛错；名称留空则退回预设名。
- **使用记录**存在工程摘要的 `lastUsedAt` 里：`saveDesign`（保存本身就是一次使用）自动刷新，单纯打开工程走 `design:touch`。
  它**只写摘要里的一个时间戳，绝不动 `revision`、也不碰 `designs/<id>/<rev>.json`**——否则用户下一次保存会撞
  `DESIGN_CONFLICT`，而报错信息完全指不到真凶（真凶在几小时前的一次「打开」上）。契约登记为 **I-29**，守卫在 `test/designs.cjs`。
- 单独开 `design:touch` 通道、而不是把记录塞进 `design:get`：后者同时服务于出片（`designs.resolveDesign` 走的就是它），
  在那条路径上写盘会让「读」带上副作用。
- 操作数现为 **58** 个（本特性新增 `design:listPresets` / `createFromPreset` / `touch` / `revealExport` / `openExport`），
  领域层测试套件 31 → **32**（`test/design-presets.cjs`），README 已同步。

## 五、脱离本系统打印（导出后一键打开）—— 已实现

「导出 PNG」把合成结果写到用户选定路径。导出成功后，界面顶部出现一条**完成条**：显示完整路径，并给两个动作。

| 动作 | 实现 | 效果 |
| --- | --- | --- |
| 打开所在文件夹 | `shell.showItemInFolder` | 在文件管理器里选中该 PNG，用户双击即可用系统看图器打印 |
| 用系统程序打开 | `shell.openPath` | 直接用系统默认程序打开 |
| 关闭 | 清掉完成条 | **只收提示，不动文件**——已导出的 PNG 仍在磁盘上 |

### 5.1 安全设计：这两个动作必须**无参**（I-28）

参数化路径在这里是明确的安全红线：`shell.openPath` / `showItemInFolder` 会拿字符串去**启动系统程序**，
渲染进程若能指定路径，就等于拿到「以当前用户身份打开任意本地文件 / 可执行文件」的能力——一条 IPC 通道
直接变成任意程序执行。所以：

- 路径**只由主进程记着**：`electron/printer.cjs` 的模块级 `lastDesignPng`，**只在导出成功后**写入
  （渲染失败或用户取消都不更新，否则「打开」会悄悄指向上一次的文件）。
- 注册表只暴露两个**零参**操作：`design:revealExport` / `design:openExport`，`params: {}`，
  `run: (_p, ctx) => ctx.printer.revealLastDesignPng()`（实现里根本不读参数）。
- 标 `gui: 'printer'`：CLI / agent 拿不到 `ctx.printer`，一律 `GUI_REQUIRED`——这条能力对 agent 是关闭的。
- `preload.cjs` 暴露给渲染层的是**零参箭头函数**，界面上无处传路径。
- 不做静默兜底：没导出过、或文件已被挪走/删掉时**明确报中文原因**，而不是「点了没反应」。

契约登记为 **I-28**（`docs/不变量契约.md`），静态守卫在 `test/api-cli.cjs` §10，
行为验证在 `test/design-export-e2e.cjs`（把 `shell` 的方法换成记录器，既验「打开了哪个文件」又不真弹窗口，
并断言「调用方硬塞的路径被忽略」）与 `test/design-e2e.cjs`（界面按钮真的接到主进程）。

这样「在批印坊里排好版 → 导出 → 到任意一台电脑/打印店印」这条链路是通的，不依赖本机装了批印坊。

## 六、明确不做（记为后续可选）

| 不做的事 | 原因 |
| --- | --- |
| 点框自动填图（空素材即槽） | 本次选择走参考框路线。若日后要加：image 图层允许 `assetId: ''` 即空槽，填图时按 `fitCover` 算裁切，槽就变成普通图片图层，下游零改动。**注意**：未跟踪的 [图片变量与批量人像出片方案](图片变量与批量人像出片方案.md) 计划用 **schema v3** 做同一处放宽（`variable` + `bindColumn`，动态图片），两者应**共用同一次放宽与同一个版本号**，不要各做各的 |
| 「适配到参考框」一键 cover | 与上一条同源，属同一个能力的简化版。本次不做 |
| 人脸检测 / 自动构图 / 抠图 | 超出范围 |
| 尺寸把握不足的国内证件 | 见 §2 注 |
