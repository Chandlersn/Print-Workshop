## 一 当前基础与范围

### 已有能力

- 数据页每份名单最多开启一个“配图”列，照片库自动跟随当前名单。
- 导入前按名单筛选，唯一匹配且可读取的照片入库；未匹配、冲突、坏图不作为有效照片入库。
- 匹配结果直接显示在表格中，缺图留空；数据页不再提供照片匹配弹窗。
- “＋变量图”按相关名单的配图状态启用，未启用时仅置灰。
- 变量图支持图层级填充方式、焦点和圆角；模板与打印中心可按行显示照片。
- 打印中心对含变量图的模板显示标签，支持现有选行、补打范围与打印历史。
- 原图默认不压缩，PDF 与归档使用原件；缩略图失败时表格可回退原图。
- alpha.8 已通过 39 项真实 Electron 验收及包内文件、隔离启动检查。这些结果属于已有的小批量验证。

### 需要补齐的基础

1. 500 张大图两轮程序导出性能已通过；PDF 大图编码质量、输出体积及真实设备仍需继续验证。
2. 默认补充缺图和替换前影响预览已实现；仍需更多真实大名单界面验收。
3. 任务暂存、失败回收和启动恢复已实现；逐系统调用断电故障矩阵仍未穷尽。
4. 稳定记录身份和部分补打防错已实现；打印前照片问题汇总、完整升级尚待验收。
5. 裁切参数目前属于变量图层，没有“只调整这一位人员”的覆盖设置。
6. 照片绑定已作为直接引用保护原件；资源分类、占用统计和可确认清理仍需完善。

### 延续的产品规则

- 自动识别已有上下文，避免反复选择名单、列与照片。
- 结果集中在表格；预检和导入进度使用页面内区域，不自动弹出遮挡操作的窗口。
- 缺图、空值和关闭配图时按已有约定留白；冲突、坏图、无效匹配值明确指出具体记录。
- 同名多图不自动任选；不得用模糊姓名匹配直接替换人员照片。
- 原件保真，性能优化优先控制资源加载、窗口数量和批次大小。
- 修改照片不改名单字段；部分出片不标记整份名单已经完成。

## 三 S1 大批量测量与稳定性

### 1 建立可重复的基准

新增计划文件 `test/photo-stress.cjs` 和独立结果目录，使用隔离数据，不读取真实用户名单。分别测量导入、打开匹配表格、打印预览、完整 PDF 导出与归档。

| 用例    | 数据组成                                           | 重点                 |
| ----- | ---------------------------------------------- | ------------------ |
| 基础对照  | 50 条记录、50 张不同图片                                | 建立耗时、内存与输出大小基线     |
| 正式大作业 | 500 条记录、500 张不同图片，约 2–8 MB/张，合计控制在现有 2 GiB 限制内 | 不用单张图片重复引用冒充压力测试   |
| 混合图片  | 横图、竖图、方图、透明 PNG、带方向信息的 JPEG，典型 1200–6000 像素    | 尺寸、方向、透明与裁切一致性     |
| 业务异常  | 缺图、空值、重名、坏图、多人共用一张图                            | 正确留白、阻断与定位，不错位、不跳行 |
| 排版边界  | 单页、多联、对折；批次末尾不足一页；只选择部分记录                      | 跨批次顺序、页数和拼版不变化     |

记录测试机器 CPU、内存、磁盘、系统版本、应用版本和图片清单哈希。采样主进程及渲染进程内存、峰值、处理耗时、文件体积和页面响应情况。

### 2 先测量，再选择优化方式

- 检查整份 HTML、图片解码、PDF Buffer 和归档复制分别占用多少内存。
- 当前 `waitPrintResources` 已有限制并发解码的处理，先验证实际效果，避免重复设计。
- 打印中心大名单预览按纸张分页加载；总人数和总页数仍展示完整作业统计。
- 若单次导出无法满足预算，则按**完整物理纸张**切批，不能把多联一页拆进两个批次。
- PDF 合并只合并页面与资源，不把页面重新栅格化。合并库选型在实测需要后进行，检查许可、Electron 兼容性、字体和图片资源保留情况。
- 输出先写临时目标，全部验证成功再发布最终文件；中途失败不能把半成品标记为成功。

### 3 进度、取消与重试

任务按“准备资源 → 生成页面 → 输出 → 归档”显示阶段及实际完成量。无法计算精确进度的阶段显示阶段名称，不制造进度百分比。

取消语义必须区分：

- 导入：停止继续读取，交由 S2 清理暂存内容；在 S2 完成前，取消只保证旧绑定不被替换，并明确记录待回收项。
- PDF：停止后续批次，销毁本任务窗口，清理临时输出，状态记录为取消。
- 直接打印：只停止尚未提交的部分。已交给系统打印队列的内容不能承诺撤回，界面显示已提交数量。
- 崩溃或失败：允许重试整个任务；成功批次可在同一输入快照下复用。跨应用重启的断点续跑不作为首轮要求，重启先报告中断并清理。

### 4 初始验收目标

以下为待实测的工程目标，不是已有性能结论：

- 在明确记录配置的 16 GB 内存 Windows 机器上，500 张测试集连续完成两轮，无崩溃、无漏页、无重复记录。
- 全部应用进程合计峰值内存目标不超过 4 GB；超出时分析并优化，不能直接修改报告认定通过。
- 页面操作响应目标在 1 秒内；可取消阶段收到请求后 2 秒内进入“正在取消”，不可中断操作完成后不再启动下一批。
- 导出耗时以首次基准为对照，同一机器、同一图片集的复测不得出现超过 20% 的未解释退化。
- 核对全部页面数量及记录顺序，抽检每个批次边界；测试用图片带唯一编号，防止仅靠页数遗漏错图问题。
- 验证 JPEG 码流、原件哈希和 PNG 解码像素保真；明确区分原文件保真与 PDF 容器内部表示。

主要改动：[printer.cjs](../electron/printer.cjs)、[print.cjs](../electron/print.cjs)、[photo-output.cjs](../electron/photo-output.cjs)、[PrintCenterView.vue](../src/views/PrintCenterView.vue)、[PhotoImportPanel.vue](../src/components/PhotoImportPanel.vue)。新增 API 必须同步能力注册、预加载白名单和测试。

## 四 S2 导入暂存与失败恢复

**进度（2026-10-13）：核心流程已实现并通过领域验收。** `photo-library.cjs` 为每次导入持久化独立任务日志和暂存原图，提交前复核名单列指纹及旧绑定指纹；活动锁限制跨进程并发导入。启动恢复根据绑定提交标记完成收尾或撤销本次新增资源；发现其他进程仍持有活动锁时，整轮恢复延后，避免与正在进行的导入争写共享素材索引。`photo:tasks` 和照片页提供最近任务状态，进度与取消仍可用。自动化测试覆盖发布前异常、真正子进程强退、发布后异常恢复、并发拒绝和旧绑定保护；还未逐个覆盖每条文件系统写操作的断电矩阵。

### 1 任务流程

```text
创建任务 → 扫描名称 → 匹配候选 → 暂存并校验原件
         → 复核名单与配图选择 → 提交资源与绑定 → 完成
                    ↘ 失败或取消 → 清理本次暂存 → 保留旧绑定
```

暂存目录位于受控数据目录内，以导入任务 ID 隔离。一次仅保留一份图片 Buffer，避免把所有原图同时放入内存。未匹配文件只记录名称及跳过原因，不复制到暂存区。

任务能力复用 `photo-library.cjs`、`designs.cjs` 与素材库的原件校验和内容哈希逻辑；暂存目录不改变原件格式或字节。

### 2 一致性规则

1. 启动时记录名单标识、配图列、相关字段值的快照指纹和旧绑定版本。
2. 提交前重新比较；名单被删除、配图列变更或相关值变化时停止提交，引导用户重新执行。无关的显示偏好变化不应让任务失效。
3. 资源以哈希去重，已存在原件只复用，记录本次实际新增的文件及索引变更。
4. 提交使用统一写入锁及持久化任务记录，覆盖资源文件、素材库索引和照片绑定的提交顺序。单个 JSON 的原子写不能替代多文件一致性。
5. “已提交绑定”的标记是恢复依据：绑定已提交则补齐收尾；未提交则撤销本次尚未被使用的新增内容。
6. 回收前重新检查共享引用和其他任务占用；不得按文件创建时间删除，不得删除本次复用的旧原件。
7. 缩略图是可重建缓存，生成失败不撤销有效原件入库；可在提交后生成。

接口草案，名称和字段在实现时由统一能力注册确认：

```js
// 主进程保存路径与快照，渲染进程只持有任务标识。
const task = {
  taskId: 'import-task-id', datasetId, column,
  mode: 'append', baseBindingFingerprint, inputFingerprint,
  state: 'staging', // scanning | matching | staging | committing | completed | recovered | rolled-back
};
// photo:tasks({ datasetId })
// photo:cancelImport({ taskId })
```

### 3 验收

- 在扫描、暂存、写原件、写素材索引、写绑定、完成标记前后分别注入失败和进程退出。
- 重启后旧绑定或完整新绑定可用，不出现索引指向未落盘文件。
- 取消不会让本次新增、未引用照片留在普通素材列表中。
- 重复内容、跨名单共享照片、另一个工程正使用的照片均受到保护。
- 恢复可重复执行两次，第二次不重复新增、不重复删除。

## 六 S4 打印前汇总与补打

**进度（2026-10-13）：稳定记录身份与安全补打已实现；页面内照片预检仍待实施。**

### 1 页面内照片预检

打印中心选定模板、名单和范围后，在操作区显示本次范围的统计，例如：

> 本次 300 人 · 已配图 286 人 · 缺图 12 人 · 空值 2 人 · 预计 300 页

点击缺图、冲突或坏图数量，在页面内展开问题表格并定位原始行号。预检不得自动唤起遮挡页面的弹窗。

预检结果采用结构化数据，页面和实际导出共用同一套判定：

```js
// 结构示意，字段以实现时的统一接口为准。
const preflight = {
  selectionFingerprint, templateRevision, bindingRevision,
  recordCount: 300, pageCount: 300,
  counts: { matched: 286, missing: 12, empty: 2, ambiguous: 0, broken: 0, invalid: 0 },
  canOutput: true,
  issues: [{ rowId, rowIndex: 7, status: 'missing', value: '示例姓名' }],
};
```

- 缺图、空值：明确“出片留白”，允许输出且保留该条记录。
- 关闭配图：显示照片留白状态，不自动开启开关。
- 同名冲突、坏图、无效值：阻止受影响范围输出，给出位置与处理入口。
- 仅检查本次选择范围；未选择人员的问题不能阻止已选择人员出片。
- 多个变量图层共享一张照片时，分别统计人数和图框数量，避免把 300 人误报为 600 人。
- 导出前复核预检快照；名单、模板或照片发生变化时刷新结果，不能沿用过期的“可输出”。

### 2 补打身份与快照

出片范围继续保存行号供界面展示，同时使用内部稳定记录 ID 定位人员，避免名单插入或删除后把旧行号套给其他人。

- 旧名单第一次迁移时为每条记录生成 ID，保存在数据集元数据中，不作为用户列显示或打印。
- 新增行创建 ID，删除行撤销 ID；编辑姓名和编号不改变 ID。所有名单写入口必须维护一致性。
- 新打印任务保存所选记录 ID、当时原始行号、名单与模板版本、照片哈希等必要快照。
- 旧历史缺少稳定 ID 时：优先使用其原有归档复现；基于当前名单重新出片必须重新确认范围，不静默按旧行号选择。
- 当前实现中，缺少稳定 ID 的旧部分历史提示用户手动重新选择范围；归档仍可直接查看。
- 区分“按当前内容补打”和“查看/复现原归档”。更新照片不得改变已经生成的历史归档。

## 十 S7 资源分类与整理

### 1 分类只改变管理方式

人员照片与设计素材继续共用内容哈希去重的原件池。管理界面提供“设计素材”“名单照片”分类，同一文件可同时属于两类。

分类依据来自导入来源及当前引用，不修改已有 `managed`/`ephemeral` 生命周期含义。人员照片默认不挤占普通素材选择列表；主动作为设计素材使用后可以在设计分类中显示。

旧数据依据照片绑定和工程引用补充分类，不能仅凭文件名猜测。无法确定来源的旧条目保留原有可见性，不自动隐藏或删除。

### 2 占用统计

按名单显示照片数量、匹配人数、逻辑占用、独占空间和共享空间；全系统实际占用按哈希去重。原件、缩略图、归档和导入暂存分别统计，避免把多份名单引用同一原件重复算成可释放空间。

### 3 引用审计与清理

原件引用扫描直接包含照片绑定、底图工程当前版本，以及模板固定引用的历史工程版本，避免素材库条目缺失时误删仍在使用的原件；照片绑定、底图工程或模板等必需引用数据不可读时，扫描报错并停止删除，不把读取失败当成无引用。打印历史达到 200 条留存上限时，先同步恢复副本，再删除被淘汰任务自己的归档目录。照片分类、占用统计、统一候选扫描与人工确认清理尚未实现。

清理前统一覆盖：

- 当前照片绑定、单人裁切覆盖及 S2 未完成任务。
- 工程当前版本、模板固定引用的历史工程版本，以及产品承诺可恢复的历史版本。
- 素材库显式保留项、活跃编辑器草稿与尚未保存的资源占用。
- 归档对源素材的实际依赖；已独立复制原件的归档单独统计，不直接删除归档目录。

当任何必需索引读取失败时，停止相应删除，不把“读取失败”当作“没有引用”。

流程为“扫描 → 显示候选及影响范围 → 用户选择 → 删除前复核 → 报告实际释放空间”。这是破坏性清理的必要确认，不用于普通导入与配图操作。实际删除沿用受控数据目录校验，不访问原照片来源文件夹。

### 4 验收

覆盖跨名单共享、同图用于设计、已归档素材、模板固定旧工程版本、正在编辑的草稿、导入进行中、索引损坏、扫描后新增引用及文件删除失败。不能只凭资源列表消失判定清理成功，必须核对文件与后续打开、打印结果。
