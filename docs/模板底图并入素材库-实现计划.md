## 2. 后端改动分步

### A. `designs.cjs`：`importImageBytes` 加 `source`
- 锚点：`electron/designs.cjs:438` `function importImageBytes({ name, base64 } = {})`.
- 改为 `importImageBytes({ name, base64, source })`，把 `source` 写入 `design-assets/<hash>.json` 的 `asset` 对象（锚点 `:432` 的 `atomicFile(metadata, JSON.stringify(asset, null, 2))`）。
- `assetInfo(id)`（`:167`）已返回 `readAsset(id).asset` → 自动带 `source`，供分流读取。
- 向后兼容：`source` 缺失时视为 `'library'`（见 §5 升级规则）。

### B. `asset-library.cjs`：落 `source` + 单向升级 + 扫描 + 分流
- **落点**：`upsert(asset, metadata, options)`（锚点 `:173`）加 `source: metadata.source ?? (existing?.source)`；新增**单向升级**：若 `existing.source === 'library'` 则保持 `'library'`，不因新写入回退成 `'template'`。
- **adopt 升级**：`adopt(assetId, metadata)`（`:199`）传 `metadata.source = 'library'`，确保「加入素材库」即升为受管理。
- **扫描指针**（方案 §2.2-B）：`referencedAssetIds()`（`:255`）补扫模板。新增 `templates.listBackgroundAssetIds()`（读模板文件返回所有 `assetId`）；`asset-library` 引入 `templates.cjs` 安全（链路无循环）。
- **分流入口**：新增 `discardIfEphemeral(assetId)`：
  - 读 `source`（`designs.assetInfo`）。
  - 若 `source === 'template'` 且 `referencedAssetIds()` 不含它 → 删原件 `design-assets/<hash>.{png,jpg,json}` + 缩略图 `design-thumbnails/<hash>.png`（走 dataDir 守卫）。
  - 否则（library / 仍被引用）→ 不删，仅由调用方撤引用。
- **孤儿清理**（§2.2-C）：`findOrphanOriginals`（`:273`）/`purgeOrphanOriginals`（`:297`）逻辑不变；`source:'template'` 孤儿本就该回收，清理时直接删；`source:'library'` 孤儿仍只在用户确认后删（现有弹窗已覆盖）。

### C. `templates.cjs`：上传改路由 + 丢弃分流
- **上传**：`uploadBackground`（`:277`）/`uploadBackgroundBytes`（`:290`）改调 `designs.importImageBytes({ name, base64, source: 'template' })`，返回 `{ assetId, width, height, suggest }`；`template.background = assetId`（不再写 `print-bg/`、不再返路径）。原 `storeBackground`/`BG_DIR` 降级为「迁移期只读兜底」（见 §5），不再新写。
- **丢弃**：`discardBackground`（`:189`）签名由 `bgPath` 改 `assetId`，改调 `asset-library.discardIfEphemeral(assetId)`（不再 `fs.unlink`、不再 `removeBgFile` 路径守卫）。
- **删模板**：`deleteTemplate`（`:193`）对 `t.background` 同样调 `discardIfEphemeral`。
- **引用判定**：`hasBackground`（`:67`）仍用 `t.background || t.backgroundDesign`，`assetId` 为真值，无需改。

### D. `api.cjs`：通道语义
- `template:uploadBackground`（`:432`）/ `uploadBackgroundBytes`（`:457`）：`run` 返回物含 `background: assetId`（前端 `TemplateView:555` 写 `t.background = result.background` 已兼容）。
- `template:discardBackground`（`:474`）：`params.path` → `params.assetId`；`run` 调 `templates.discardBackground(assetId)`。

### E. 渲染解析（双形态兼容，无 UI 改动）
- `TemplateView.vue:367` `bgUrl`：`activeTpl.background` 为 `asset_<sha256>` → 返 `pp://media/design-assets/<hash>.png`；仍为 `print-bg/...` 旧路径 → 原样返（兼容存量）。
- `render-engine.cjs:302` `inlineUrl(template.background)`：加判断——`asset_<sha256>` → 读 `design-assets/<hash>` 字节内联（同 `design-layout.cjs:188` 读 `asset.path`）；`print-bg/...` → 原 `readMediaFile` 路径解析。
- `main.cjs:56` `pp://` 处理器按 rel 映射 dataDir，传 `design-assets/<hash>.png` 即可，无需改。

### F. 迁移（存量 `print-bg/` 背景）
- 新增 `templates.migrateBackgrounds()`：遍历模板，若 `background` 匹配 `/^print-bg\/.+\.(png|jpe?g)$/`，读该文件字节 → `designs.importImageBytes({ name, base64, source: 'template' })` → 把 `background` 替换为 `assetId` 并 `persistAll`。
- 调用时机：应用启动 / 模板首次加载时跑一次（幂等：已是 `assetId` 跳过）。
- 迁移完成后 `print-bg/` 目录留空，后续版本可废弃（不主动删用户数据目录）。

## 3. 守卫 I-33（静态契约）

`docs/不变量契约.md` 新增：
> **I-33 模板底图走素材库原件**
> - 模板底图必须引用 `design-assets/` 内容寻址原件（`template.background` 为 `asset_<sha256>`），不得再存 `print-bg/` 路径副本。
> - `discardBackground` 对 `source:'library'`（或已归档）原件**不得删除**；仅 `source:'template'` 且无引用时可删（即时删除语义）。
> - 原件生死归素材库（`asset-library`），模板层只持引用。

`test/invariants.cjs` 的 `CONTRACT` 登记 I-33（钉源码文本：如 `uploadBackground` 调 `importImageBytes`、`discardBackground` 不再含 `fs.unlinkSync`/`removeBgFile` 直接删路径、新增 `discardIfEphemeral`）。

## 4. `source` 升级规则（锁死）

- 取值：`'template'`（模板页上传）/`'library'`（底图制作导入）。
- 缺失 → 默认 `'library'`（受管理，绝不误删既有图）。
- **单向升级**：`template → library` 允许（adopt/加入素材库），`library → template` 禁止。即一旦进过素材库即受管理。

## 6. 测试清单（`test/template-asset-library.cjs` 新增）

1. 模板上传底图 → `template.background` 为 `asset_<sha256>`，原件在 `design-assets/`，`asset-library.json` 条目 `source:'template'`。
2. 模板 discard（`source:'template'`、无他引）→ 原件被删；重新 `referencedAssetIds` 不含它。

5. 去重升级：模板上传同图 → `adopt` 为 library → `source` 升 `library`、discard 不再即时删。
6. 存量 `print-bg/` 背景 `migrateBackgrounds` → 迁为 `assetId`，`bgUrl`/`inlineUrl` 渲染正常。
7. `discardBackground` 不再直接 `fs.unlink` 路径（I-33 守卫）。
8. 不变量契约 `npm test` 仍全绿（含 I-33 新增断言）。

## 8. 风险与回滚

- **风险**：`print-bg/` 迁移若读不到文件（用户手删）→ 跳过并留 `background` 空 + 前端 `onBgError` 兜底（已有）。
- **风险**：`asset-library` 引 `templates` 循环依赖 → 已确认链路无回指，安全。
- **回滚**：本功能独立提交；如需回退，`git revert` 该提交即可，不影响 M1/内置底图位置模板已提交代码。
