# 批印坊 v0.5.0 开发计划

> 编写日期：2026-10-09。当前底图编辑功能基线为 v0.4.0，建议下一版使用 v0.5.0。
> 本文聚焦底图制作的下一阶段，状态为待开发。代码是关键逻辑示例；标注为“拟新增”的接口、辅助函数和文件需要后续实现，不代表当前已经存在。

## 一、本版目标与范围

让用户能反复使用自己的图片素材，把可编辑底图完整迁移到另一台电脑，并完成常用的渐变与阴影装饰。延续现有毫米坐标、原图存储和统一渲染机制，导出清晰度与字段位置一致性作为发布门槛。

| 优先级 | 功能 | 本版交付范围 | 用户获得的能力 |
| --- | --- | --- | --- |
| P0 | 本地素材库 | PNG/JPEG 原图入库、缩略图、名称、标签、搜索、收藏、归档与恢复 | Logo、纹理、装饰图导入一次，多份底图复用 |
| P0 | 工程包导入导出 | `.ppdesign` 工程包；固定版本、图片原件、字体依赖、导入检查与冲突处理 | 换电脑继续编辑、备份或交接底图 |
| P1 | 线性渐变 | 画板、矩形、椭圆；2～8 个色标、方向、色标透明度 | 制作渐变背景和装饰块 |
| P1 | 基础外阴影 | 矩形、椭圆；单个阴影的颜色、透明度、偏移、模糊 | 制作简单卡片、边框和浮起效果 |
| 全程 | 输出与兼容性 | 旧工程、固定版本模板、PDF、PNG、撤销及草稿回归 | 继续稳定出片 |

阴影必须通过实际 PDF 保真验证才进入交付范围。若底层打印引擎导致照片降采样或整页栅格化，则调整实现或顺延该项，其余功能可独立交付。

嵌套分组、整组缩放旋转、径向渐变、图片/文字/组阴影、蒙版、混合模式、PSD/Compositor 工程互开、云素材库和专业 CMYK 管理放在后续版本。素材自动物理清理也暂缓，避免破坏历史版本与本地草稿。

## 三、本地素材库

### 3.1 使用流程

1. 底图编辑器增加“素材”侧栏，支持导入图片、搜索、标签筛选与收藏。
2. 点击素材插入画板；按当前画板尺寸计算初始大小，保持原图比例。
3. 素材详情显示原始像素与格式；放入画板后显示当前尺寸对应的有效 DPI。
4. 修改名称、标签、收藏只改变素材库信息；“归档”从常用列表隐藏，支持恢复。
5. 已有工程的图片可通过“加入素材库”建立条目。新导入图片同步入库；不自动把所有遗留文件当作用户素材。

### 3.2 存储边界

继续使用 `design-assets/<SHA-256>.png|jpg` 保存原件，新增 `asset-library.json` 保存展示信息。缓存缩略图放在 `design-thumbnails/`，建议最长边 320 像素，可随时重建。

同一内容对应一份原件；显示名称、标签、收藏、归档时间独立于工程资产描述。修改库名称不改写旧工程，归档不删除原件。缩略图只能用于素材列表，画板、打印和工程包始终读取原件。

```js
// 拟新增：素材库条目。assetId 关联现有内容寻址的原始图片。
const libraryEntry = {
  assetId: 'asset_<sha256>',
  displayName: '学校校徽',
  tags: ['学校', '标识'],
  favorite: true,
  archivedAt: null,
  createdAt: '2026-10-09T00:00:00.000Z',
  updatedAt: '2026-10-09T00:00:00.000Z'
};

// 拟新增：后端入库逻辑；显示元数据不参与原件哈希。
async function importLibraryImage(filePath, metadata) {
  const asset = await assets.importOriginal(filePath); // 复用现有图片校验与存储
  await library.upsertMetadata(asset.id, metadata);    // 同内容合并条目、恢复归档
  thumbnails.schedule(asset.id);                      // 限并发，失败不影响原图入库
  return { asset, thumbnailKey: thumbnails.key(asset.id) };

```

素材服务拟提供 `asset:list/get/importFiles/update/archive/restore`；列表分页并限制单页数量。IPC 传递素材标识和元数据，原件路径由后端解析，不开放任意文件读取。

### 3.3 插入素材与异步编辑保护

素材加载完成时，用户可能已经切换工程。为每次打开/新建工程维护 `sessionToken`；切换后旧请求不能修改新画板。同一工程内仍使用最新状态提交，插入图片与新增图层合并为一次撤销记录。

```js
// 拟新增的前端会话接口示意。
async function insertLibraryAsset(assetId) {
  const session = editor.sessionToken;
  const asset = await api.assetGet({ assetId });
  if (session !== editor.sessionToken) return;

  editor.commit('插入素材', current => {
    const layer = makeImageLayer(asset, current.artboard); // 新 ID、等比适配画板
    current.assets[asset.id] = asset;                      // 原件描述，不填缩略图
    current.layers.push(layer);
  });
}
```

## 四、可编辑工程包

### 4.1 导出与导入规则

**导出固定的已保存版本。** 工程有未保存修改时，提供“保存后导出”和“导出已保存版本”。前者使用保存接口返回的 `{id, revision}`，后者明确显示版本号；新建未保存工程需要先保存。开始导出后继续编辑，不改变此次导出的内容。

工程包包含该版本全部图层所需的图片和字体依赖，包含隐藏图层；可以在包内副本中移除完全未被引用的图片描述。保留分组、参考线和效果。包只含一个底图版本，不包含名单数据、模板变量字段、撤销历史或本机草稿。

**导入始终创建副本。** 先检查再显示工程尺寸、图层数量、资源体积、字体问题，确认后生成新工程 ID、版本 1。原工程 ID 仅用于来源记录。同名工程不覆盖，当前画板保持原状；导入后点击“打开副本”，通过现有草稿保护流程切换。

### 4.2 文件结构与依赖清单

采用 ZIP 容器，扩展名 `.ppdesign`。包版本 `packageVersion` 与工程格式 `schemaVersion` 独立演进。归档编解码封装在拟新增的 `packageCodec` 中；实现时选择支持逐条读取、字节限额与取消的库，不自行编写 ZIP 解码器。

```text
示例.ppdesign
├── manifest.json             # 包版本、来源版本、资源哈希与大小、字体依赖
├── project.json              # 可编辑工程；资源关联通过清单解析
├── images/<sha256>.png       # 图片原始字节，也允许 .jpg
└── fonts/<sha256>.ttf        # 可选字体原件，扩展名沿用受支持格式
```

`manifest.json` 每项资源必须记录角色、SHA-256、实际字节数和格式；字体依赖区分“已内嵌”“需本机提供”。不接受远程 URL 或包外路径。依赖收集必须遍历隐藏图层，防止重新显示图层时丢图、丢字体。

```js
// 拟新增：保存完成时拿到准确版本，不再次读取可能已经变化的“最新版”。
async function exportProjectPackage({ currentRef, saveFirst, targetPath }) {
  const ref = saveFirst ? await editor.saveSnapshot() : currentRef;
  if (!ref?.id || !ref.revision) throw new Error('请先保存底图工程');
  return api.designPackageExport({ id: ref.id, revision: ref.revision, targetPath });
}

// 拟新增：从已经校验的工程快照收集依赖。
function collectPackageReferences(doc) {
  const imageIds = new Set();
  const fontFamilies = new Set();
  for (const layer of doc.layers) { // 不根据 visible 过滤
    if (layer.type === 'image') imageIds.add(layer.assetId);
    if (layer.type === 'text') fontFamilies.add(layer.fontFamily);
  }
  return { imageIds: [...imageIds], fontFamilies: [...fontFamilies] };
}
```

包导出先写同目录临时文件，写完检查清单和完整性，再完成目标文件替换。失败或取消保留原目标文件，使用平台适配的替换流程验证覆盖行为，不直接向目标路径边写边覆盖。

### 4.3 字体携带与冲突

用户可以选择携带有权分发的已上传字体；系统字体不自动打包。未携带字体列入依赖清单，不能承诺跨电脑字体完全一致。导入端缺少字体或无法确认匹配时，用户需提供字体文件或明确选择替代字体；替换结果显示在导入摘要中，未解决依赖不能完成导入。

处理顺序：

1. 校验字体格式、字节数与哈希。
2. 内容和绑定身份一致时复用本地字体。
3. 同名不同内容时，为导入字体生成稳定别名，例如 `PP_Font_<完整SHA256>`；文件名与字体绑定名保持一致。
4. 先生成全部字体的最终绑定映射，再一次性重写导入副本中的 `layer.fontFamily` 和 `fontAssets`；原工程及历史版本继续使用原字体。
5. 文件名按 Windows 大小写不敏感规则检查，同时检查规范化后的 CSS 字体家族名，避免两种名称空间发生冲突。

```js
// 拟新增：内嵌字体需改别名的分支；冲突规划已验证最终绑定与其余依赖相容。
function bindImportedFonts(doc, verifiedFonts) {
  const bindings = new Map(verifiedFonts.map(font => {
    const family = `PP_Font_${font.sha256}`;
    return [font.originalFamily, {
      family, fileName: `${family}.${font.validatedExtension}`, source: font.stagedPath
    }];
  }));
  const fontAssets = { ...doc.fontAssets };
  for (const originalFamily of bindings.keys()) delete fontAssets[originalFamily];
  for (const layer of doc.layers) {
    if (layer.type !== 'text') continue;
    const binding = bindings.get(layer.fontFamily); // 每层按原名查找一次，避免连锁替换
    if (binding) layer.fontFamily = binding.family;
  }
  for (const binding of bindings.values()) {
    fontAssets[binding.family] = binding.fileName;
  }
  doc.fontAssets = fontAssets;
  return [...bindings.values()];
}
```

`verifiedFonts` 必须来自后端验证结果。别名文件用排他创建，已存在时验证内容一致。普通字体上传也改用同一冲突处理规则：同名同内容复用，同名不同内容建立新绑定，不覆盖旧文件；内容别名字体一经发布保持不可变，防止后续上传破坏历史工程。字体展示名称另存元数据，界面可继续显示原始名称。

### 4.4 导入检查、资源限制与恢复

导入分两步：`inspect` 将包读取到后端管理的暂存区并返回检查令牌；`commit` 只使用该令牌对应的已验证内容。令牌绑定暂存快照，源文件在检查后被替换不能改变最终导入内容；令牌设有效期并支持取消。

拟定初始限制如下，实施时用代表性大工程校准：

| 项目 | 限制 |
| --- | --- |
| 图片 | 沿用单张 64 MiB、8000 万像素、工程累计 512 MiB |
| 字体 | 单个 32 MiB、累计 128 MiB |
| 工程 JSON | 32 MiB；解析后继续遵守现有图层、文字及画板限制 |
| 清单 | 1 MiB；字段长度、资源数量受限 |
| 总解压体积 | 768 MiB，按实际流出字节计数 |
| 条目数量 | 650 个；另设解码超时、压缩比和取消检查 |

只接受清单列出的规范资源路径。拒绝绝对路径、`..`、反斜杠变体、重复及大小写冲突条目、链接、加密包、分卷包、Windows ADS；每条实际资源都校验大小、哈希和文件签名。不能只相信 ZIP 头部声明的大小；不能先整体解压再检查。

图片超限应明确提示原因，由用户调整工程，不自动压缩原图。大文件不经过 base64 IPC 往返，界面只接收任务 ID、进度与结果。

提交采用“准备资源 → 持久化事务记录 → 发布不可变文件 → 最后发布新工程索引”的流程。现有单文件原子写入不等于多文件事务，需要新增恢复日志。

```js
// 拟新增：简化的事务骨架；这些事务辅助函数尚未实现。
function commitInspectedPackage(token) {
  const plan = stagedImports.requireValidated(token);
  return withResourceWriteLock(() => { // 同步锁；耗时解包已在锁外完成
    const tx = transactions.prepare(plan); // 分配新工程 ID，先落盘恢复记录
    try {
      recheckResourceConflicts(plan);
      publishImmutableResources(tx, plan); // 排他创建；已有文件必须哈希一致
      const ref = publishNewDesignLocked(tx, plan); // 工程索引最后发布
      transactions.markCommitted(tx, ref);
      return ref;
    } catch (error) {
      return transactions.reconcileOrThrow(tx, error);
    }
  });
}
```

实现要求：

- 锁覆盖工程包提交与涉及资源的字体写入，锁内不等待异步操作。抽出内部 `publishNewDesignLocked`，避免锁内再次调用会获取同一锁的公共 `saveDesign`。
- 暂存区与数据目录在同一文件系统；资源发布中间态不能出现在字体选择器。字体可见性以“工程索引和文档哈希确认发布”为依据，不能只看事务提交标记；选择器、字体解析和渲染 CSS 共用该判定，保证已发布工程立即可用其字体。无法确定状态时先恢复事务，再开放相关读取，禁止静默回退。
- 索引已发布但提交标记没写完时，恢复程序核对目标工程 ID、版本与文档哈希后认定成功，重复提交返回同一个结果。
- 索引未发布时撤销该事务的可见记录；清理仅限事务自己拥有的暂存内容和确认无引用的新字体。保守保留图片原件，绝不删除此前已有或共享的资源。
- 取消在提交前生效；进入索引发布阶段后先完成或恢复一致状态，再返回明确结果。剩余磁盘不足、应用崩溃、重复点击都要验证。

## 五、渐变与基础阴影

### 5.1 工程格式版本 3

保留现有 `artboard.background`、形状 `fill` 纯色字段，增加可选的 `backgroundPaint`、`fillPaint` 和 `shadow`。新效果存在时优先使用，关闭时删除对应字段，恢复纯色。旧版本工程读取时不自动重写历史文件。

```js
// 拟新增字段；角度定义为 0° 向右、90° 向下。
const linearPaint = {
  type: 'linear', angle: 90,
  stops: [
    { offset: 0, color: '#ffffff', opacity: 1 },
    { offset: 1, color: '#dbeafe', opacity: 1 }
  ]
};
const shapeShadow = {
  dxMm: 1, dyMm: 1.5, blurMm: 1, color: '#000000', opacity: 0.2
};

// 拟调整：调用前已完成新字段及适用图层类型的严格校验。
function resolveSchemaVersion(input, normalized) {
  let version = input.schemaVersion ?? 1;
  if (![1, 2, 3].includes(version)) throw new Error('不支持的工程格式版本');
  if (normalized.groups.length || normalized.guides.length) version = Math.max(version, 2);
  if (hasSupportedEffects(normalized)) version = Math.max(version, 3);
  return version;
}
```

校验要求：数值有限；渐变色标 2～8 个、位置与透明度为 0～1、按位置稳定排序，首尾覆盖 0 和 1；颜色使用受支持的十六进制值。阴影偏移暂定 ±50 mm、模糊 0～10 mm；`blurMm` 定义为高斯标准差。阴影只允许矩形、椭圆，禁止透传任意 CSS、SVG 或滤镜字符串。

格式 3 输入规范化后保持格式 3。先识别并校验效果字段，再计算版本，不能先丢弃未知字段而让用户误以为效果已保存。旧版应用遇到版本 3 应明确提示升级，不能降级保存。撤销恢复已有的旧格式快照沿用现有历史机制。

### 5.2 统一渐变渲染与实例标识

继续由共享渲染器生成编辑器、模板预览、PDF 与 PNG 内容。渐变使用 SVG，局部 `viewBox` 按图层毫米尺寸建立，设置 `gradientUnits="userSpaceOnUse"`，避免非正方形图层采用包围盒坐标后方向发生视觉偏差。[SVG 渐变规范](https://www.w3.org/TR/SVG2/pservers.html#LinearGradients)

```js
// 拟新增：把方向转换为局部毫米坐标的端点，覆盖矩形在该方向的投影。
function linearEndpoints(w, h, angle) {
  const rad = angle * Math.PI / 180;
  const dx = Math.cos(rad), dy = Math.sin(rad);
  const half = (Math.abs(w * dx) + Math.abs(h * dy)) / 2;
  return {
    x1: w / 2 - dx * half, y1: h / 2 - dy * half,
    x2: w / 2 + dx * half, y2: h / 2 + dy * half
  };
}

// 拟新增：每个 HTML 文档创建一个分配器；编号由程序生成，不含用户文本。
function createEffectScopeAllocator() {
  let instanceIndex = 0;
  return () => {
    const instance = instanceIndex++;
    let effectIndex = 0;
    return () => `pp_effect_${instance}_${effectIndex++}`;
  };
}
```

每份实际底图实例拿到独立的 ID 分配函数，每个渐变和滤镜再分配 ID。多联每个格子、对折两面都独立生成，不能把含相同 `id` 的 HTML 复制多遍；仅使用工程 ID 或图层 ID 也不足以区分重复实例。多个编辑预览共存时，同样从所在文档共享分配器。

保持“资源准备一次、几何内容按实例生成”：图片 URL 与字体 CSS 继续去重，避免解决 SVG ID 冲突时把大图重复编码。渐变显式设置 `color-interpolation="sRGB"`，各输出路径使用同一组色标与端点。

### 5.3 阴影单独渲染

阴影根据形状填充与描边的实际 alpha 生成，包括透明渐变；绘制在该图层主体下面，与主体共享旋转和图层透明度。只过滤用于阴影的形状副本，主体 SVG 保持独立；照片和文字仍使用既有渲染路径。

滤镜区域会裁切超出的效果，因此必须计算留白，不能依赖默认区域。[滤镜区域规范](https://www.w3.org/TR/filter-effects-1/#FilterRegion)

```js
// 拟新增：bounds 包括形状描边的实际边界；单位均为局部毫米。
function shadowRegion(bounds, shadow) {
  const pad = 4 * shadow.blurMm + 0.25; // 初始工程余量，需用边缘像素验收
  return {
    x: bounds.x + Math.min(0, shadow.dxMm) - pad,
    y: bounds.y + Math.min(0, shadow.dyMm) - pad,
    width: bounds.width + Math.abs(shadow.dxMm) + 2 * pad,
    height: bounds.height + Math.abs(shadow.dyMm) + 2 * pad
  };
}
```

滤镜链为 `SourceAlpha → feGaussianBlur → feOffset → feFlood + feComposite(in)`，只输出阴影；主体单独绘制。`filterUnits`、`primitiveUnits` 均设为 `userSpaceOnUse`，滤镜及必要的 primitive 子区域显式使用计算范围，采用 `color-interpolation-filters="sRGB"`。形状容器允许效果溢出，最终仍在画板及版式单元边界裁切，防止串到相邻格子。

Chromium 可能把滤镜部分栅格化，不能据此承诺阴影是纯矢量。开发第一步制作带大图、中文、渐变、阴影重叠的真实 PDF 样张，检查照片原始码流/像素、文字可选取和局部效果分辨率；通过后再接完整 UI。

### 5.4 PNG 与性能预算

透明导出需要同时移除画板纯色和画板渐变，保留用户图层及其阴影：

```js
// 拟调整：只修改导出快照，不改变编辑器文档、版本或撤销记录。
function makePngExportSnapshot(normalizedDoc, transparent) {
  const snapshot = structuredClone(normalizedDoc);
  if (transparent) {
    snapshot.artboard.background = 'transparent';
    delete snapshot.artboard.backgroundPaint;
  }
  return snapshot;
}
```

像素尺寸继续为 `round(mm × dpi / 25.4)`，沿用最大边 16384 像素、4000 万像素及 768 MiB 估算工作内存限制。新增滤镜预算：把效果区域换算到目标 DPI，计入旋转后的包围盒、同时存在的效果及多个中间 RGBA 缓冲区。具体缓冲系数以实测校准，超预算明确拒绝或让用户选择较低 DPI，不后台降低质量。

编辑中连续拖动色标、阴影滑块按一个手势合并撤销；输入框提交后规范化数值。缩略图延迟生成，主画布始终使用正式渲染逻辑。
