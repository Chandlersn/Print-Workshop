# 批印坊（PrintPress）开发计划

> 配套文档：[开发方案.md](./开发方案.md)（架构、选型、数据模型的权威定义）。
> 节奏：每个里程碑遵循「基线 → 改动 → 回归 → 真实数据冒烟 → 下结论」。
> 估时为专注工作量，非日历承诺。

---

## 里程碑总览

| 阶段 | 内容 | 估时 | 交付物 |
|---|---|---|---|
| M0 | 项目骨架 | 0.5d | 空壳应用跑通 + 宣纸墨韵基线 |
| M1 | 数据源（导入层） | 1.5d | Excel/CSV 导入 → 预览 → 数据集管理 |
| M2 | 模板工坊（画布） | 2d | 底图 + 拖拽排版 + 字体管理 |
| M3 | 渲染引擎 + 打印中心 | 2d | 批量打印 / PDF 导出 / 留痕归档 |
| M4 | 打磨与对拍 | 1.5d | 吸附/多选/撤销/填充率/暗色 全量补齐 |
| M5 | 产品化底座 | 1.5d | NSIS 安装包 + 示例模板库 + 首启引导 |

MVP = M0~M3 跑通端到端；M4/M5 是从「能用」到「给人用」。

## M0 项目骨架（0.5d）

- [ ] 目录结构：`electron/`（主进程）、`src/`（Vue3 渲染进程）、`data/`（运行时数据）、`docs/`、`assets/`
- [ ] `package.json`：electron + vue3 + vite + electron-builder 脚本链（dev / build / dist）
- [ ] 主进程最小壳：窗口创建 + ipc-gateway 骨架 + contextBridge 白名单暴露
- [ ] 渲染进程最小壳：三页导航（数据 / 模板 / 打印中心）+ 宣纸墨韵 token（--paper/--line/--cinnabar/--stone）
- [ ] dataStore 骨架：JSON 原子写（临时文件 + rename）+ 读取
- [ ] **首个安装包冒烟**：electron-builder 出一个未签名 NSIS 包，确认本机装得上、跑得动（风险前置）

验收：`npm run dev` 打开三页空壳；安装包本机可安装启动；主题 token 全局生效。

## M1 数据源（1.5d）

- [ ] CSV 导入：多编码检测（UTF-8 / GBK 优先级），RFC 4180 引号规则
- [ ] Excel 导入：exceljs（或 SheetJS，M1 实测定稿）；仅取第一个工作表，合并单元格取左上值（入口宽松）
- [ ] 列规范化：表头清洗 → 规范 `key`；`alias` 默认等于原表头；列名转换**全项目唯一函数**（源项目双轨命名教训）
- [ ] 字段目录派生：从真实行数据派生列清单 + fill 填充率 + 分层可打印过滤（黑名单→命名语义→值形态→长度，字面量集合用真实数据校准）
- [ ] 数据页 UI：导入入口 → 预览确认（前 20 行 + 列清单 + 填充徽标）→ 数据集列表（切换/删除/重命名列别名）
- [ ] IPC：`dataset:import / list / get / delete / renameColumn`、`catalog:fields`

验收：用 3 份真实乱数据（GBK 老表格 / 带合并单元格 xlsx / 混乱 CSV）导入不崩、预览可见、字段目录与填充率正确；入口零拦截。

## M2 模板工坊（2d）

- [ ] 底图上传：存应用数据目录，读真实像素尺寸 → 建议纸张（比例匹配）
- [ ] 画布：百分比坐标系，字段框拖拽定位、字号/颜色/对齐/加粗/字体属性面板
- [ ] 字体管理：系统字体检测（Windows 注册表优先 + 候选清单存在性检测）+ 用户上传字体（@font-face 注入 + FontFace API 画布预览）+ 删除前引用校验
- [ ] 模板 CRUD：全量快照写 templates.json；纸张选择（A4/A5/自定义）+ 底图纸张比例差 >2% 变形预警
- [ ] CustomSelect 统一组件（带分组：系统字体/上传字体），全页无原生 select

验收：上传底图 → 加字段 → 拖到任意位置 → 重开应用排版不丢；字体上传后画布即见即所得。

## M3 渲染引擎 + 打印中心（2d）

- [ ] `render-engine.js`：模板 × 记录 → HTML（字段样式生成、HTML 转义、@font-face 注入、分页一记录一页）
- [ ] **对拍验证**：同一数据同一模板，与源项目 workbench 引擎输出比对字段取值/坐标/字体，差异清零
- [ ] 打印通道：`printToPDF`（导出/归档）+ `webContents.print`（直接打印）
- [ ] 出口校验：打印前直查数据集，勾选字段空值明细弹窗，可中断可放行（保留「仍要打印」）
- [ ] 打印中心 UI：批量发起（选数据集 → 勾选行 → 选模板 → 校验 → 生成）+ 留痕表 + 归档 PDF 回看
- [ ] 归档：按月分目录存快照 PDF；`print_jobs` 留痕（模板/数据集/行数/时间/快照路径）
- [ ] IPC：`print:generate / validate`、`job:list / openSnapshot`

验收：**端到端冒烟**——导入真实名单 → 套模板 → 批量 120 人 → 打印机出纸 / 导出 PDF → 打印中心能回看每一份归档件；空值字段弹窗明细准确。

## M4 打磨与对拍（1.5d）

- [ ] 画布吸附对齐（三等分线 + 字段间左中右/上中下，阈值 6px，朱砂红辅助线）
- [ ] 多选对齐（Ctrl+点选，左对齐/水平居中/垂直等间距，视觉边缘换算回锚点）
- [ ] 撤销重做（快照栈 50 条：拖拽首次位移入栈、方向键 600ms 合并、属性 change 钩子）
- [ ] 键盘微调（方向键 0.1%、Shift 1%，tabindex 接收）
- [ ] 无数据字段半透明 + 红虚线框（悬停提示「打印时将留空」）；零填充字段灰显沉底
- [ ] 行内打印历史（模板/数据集反查 N 次、最近时间）+ 一键重打
- [ ] 暗色模式全页验证（对比度专项，源项目白底白字教训）

验收：源项目打印三件套的全部打磨项在本项目等价可用；暗色模式逐页人工过检。

## M5 产品化底座（1.5d）

- [ ] 示例模板库：内置证书 / 工牌 / 邀请函 / 标签 4 套模板 + 示例数据
- [ ] 首次启动引导：「用示例走通全流程」三步引导（导入示例 → 选模板 → 打印）
- [ ] electron-builder 正式配置：应用图标、安装目录、数据目录（%APPDATA%）规划
- [ ] electron-updater 接口位（版本上报 + 检查更新空实现）
- [ ] settings 预留授权/账号字段位（本期不实现）
- [ ] README（面向使用者）+ 最终安装包全流程冒烟（安装 → 示例走通 → 卸载数据残留检查）

验收：把安装包发给一个没用过的真人，不看文档能 10 分钟内打出一张证书。

## 里程碑后的候选方向（不排期）

> **范围前提**：数据集与模板由用户准备并已审核。本工具只做「快速简单地做好模板 + 批量化出片」及其细节补充——数据集生命周期管理不在此列。

**因子内加法（按序执行，契约不动）**

- **行级勾选**（已完成 2026-10-01）：默认全选；可取消全选后按关键词查询、逐个勾选，用于补打 / 分批。**同一份勾选同时作用于「直接打印」与「导出 PDF」**，不做两套范围。任务记录加 `rows` 字段；勾选为一次性 UI 状态，数据集变更即失效重选。
  - **回写规则**：仅「本次范围 = 全部行」才回写数据集「已打」状态（侧栏徽标 / 变色）；部分出片不回写但照常留痕。打印历史标注范围（如「部分 3/120」），打印中心统计条主数字只算全量、另标补打次数。
- **多联 / 双联排版**（**已完成 2026-10-01**）：一页多记录（N-up）。底图从「整页一张」变为「单个成品图」，系统按纸张与成品尺寸自动算行列数（如 A4 → 2 列 × 5 行）并居中，画布切换为「单个成品」设计，可选裁切线；内置 1 寸 / 2 寸 / 5 寸等常见成品尺寸预设。
- **数据目录体检（可选）**：删模板已连带清理底图（`deleteTemplate`），主路径无泄漏；仅历史遗留 / 手动残留需扫描，优先级低。
- **清理已下线功能残留**（**已完成 2026-10-01**）：按「快速简单」原则**全删净**——`print:exportGrouped` 链路、`dataset.columnValues` + `catalog:values`、打印通道的 `filters` 参数、`rows.cjs` 的 `applyFilters`（文件收缩为 `placeholder.cjs`）。`modeLabel` 的「已下线」映射保留 1 行防历史记录裸奔。

**细节补充（待真实需求驱动）**

- **映射记忆**：换绑本身已实现（`rebindDataset` + 字段匹配预检）；缺的是按列 key 自动重映射。视真实换绑频率再定。

**工程体检**

- **存储性能压测**（**已完成 2026-10-01**）：实测 5 万行（8.6MB）导入 158ms / 改一格 113ms / 字段目录 70ms，线性增长、完全可用 → **阈值放宽到 10 万行或 20MB**；任务 O(n²) 在真实使用中不存在；瓶颈是「整文件重写」机制；且「升 SQLite」与「零原生依赖」原则冲突，真要上应等 Electron 内置 Node ≥22 用 `node:sqlite`。详见 `docs/存储性能基准.md`。

**升格候选（先答契约）**

- **模板打包分享**：包格式契约 + 底图版权声明，v0.1 阶段只记账。

**移出范围 / 暂不做**

- 份数控制——2026-10-01 跳过（经确认「每人 N 份」非真实需求）
- 图片导出（模板效果图，T 因子）——2026-10-01 放弃：窗口尺寸被系统钳制在屏幕工作区，A4 竖版整页塞不进窗口；CDP `Page.captureScreenshot` 挂死；离屏被钳制且 `paint` 崩进程。分块截图 + canvas 拼接能出整页图，但同进程连续导出有未解阻塞，性价比不成立
- 数据集管理面（重命名 / 复制 / 导出 CSV）——数据集由外部准备并已审核（行级勾选是「出片范围」，非数据集导出）
- 快递面单模板、电子面单 API 对接（需服务商资质）
- Word 合并导出
- 自更新全自动化（降级为「下载页直达 + 版本对比」）

## 工程纪律（全程有效）

1. 「DB 列名 ↔ 记录键」转换全项目唯一函数，禁止各模块自写命名假设
2. 字面量过滤集合先查真实数据校准再定（避免误杀业务字段）
3. 改主进程代码必须重启 Electron 才生效；「改了没用」先核对运行版本
4. 每个里程碑收尾跑：构建通过 + 全页人工冒烟 + 真实数据过一遍
5. `data/` 为运行时用户数据，不进 git、不进安装包
