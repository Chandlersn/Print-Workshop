# 模板底图并入素材库（统一方案）

> **【后期改名】** 本文以下用 `source: 'template'` / `'library'`（当时的名字）。v0.5.0 后期已改名为
> **`ephemeral`**（临时件）/ **`managed`**（受管理）——因为这两个值描述的是**生命周期策略**而非**来源**，
> `template` 当名字会让人以为只跟模板有关。旧值**读时兼容**（存量数据无需迁移）。
> 当前权威定义见 `docs/不变量契约.md` 的 I-33；本文保留当时的决策语境，不改写正文。

> 决策存档：2026-10-10 与用户敲定。目标＝把「模板页上传的底图」与「底图制作导入素材库的图」统一到同一套存储与管理，但**两类底图各守各的删除语义**。
>
> 约束（用户硬性要求）：
> - 模板页 UI **零改动**（不新增任何按钮 / 界面功能）。
> - 素材库弹窗 UI **零复制**（直接复用底图制作页现有的 `AssetLibrarySidebar`）。
> - 通过「元数据分流切口」让两类底图走不同生命周期。

---

## 1. 现状（为什么是两套池子）

| | 模板页底图 | 底图制作素材（M1 素材库） |
|---|---|---|
| 落盘目录 | `data/print-bg/<时间戳>-<随机>-<名>.<ext>`（平铺文件） | `data/design-assets/<sha256>.<ext>` + `.json`（内容寻址） |
| JSON 引用 | `template.background` = **路径字符串** | `layer.assetId` = `asset_<sha256>` |
| 写入入口 | `template:uploadBackground` / `uploadBackgroundBytes` | `designs.importImageBytes` / `importImageFile` |
| 删除 | `template:discardBackground` **直接 `fs.unlink` 文件** | 永不自动删（I-31③），仅归档（I-31②） |
| 去重 / 缩略图 / 标签 | 无（注释明写「一个文件只归一条模板用，不存在共用」） | 有（同内容一份原件、320px 缩略图、`asset-library.json` 元数据） |
| 是否进素材库扫描 | ❌ `referencedAssetIds()` 不扫 `print-bg/`、不扫模板 | ✅ 素材库就建在它上面 |

两个池子互不相通是 M1 的**范围缺口**，不是刻意分割。

---

## 2. 统一设计（存储层合并，UI 不动）

模板页照旧上传（现有按钮 + 拖拽/粘贴），但上传落点从 `print-bg/` 改到素材库的内容寻址池 `design-assets/`：

- `template.background` 从「`print-bg/...` 路径」改为「`asset_<sha256>` 引用」。
- 因为素材库弹窗（`AssetLibrarySidebar`）读的是 `asset-library.json` 全量，**模板底图一进这口池子，弹窗里自动就能被管理**（搜索/标签/收藏/归档/清理）——无需复制 UI。
- 渲染层只改「引用解析」，不改任何交互。

### 2.1 元数据分流切口：`source`

在 asset 条目（`asset-library.json`）与原件的 metadata（`design-assets/<hash>.json`）上加字段：

```
source: 'template'   // 从模板页上传（受即时删除）
source: 'library'    // 从底图制作导入素材库（受 I-31 管理，不即时删）
```

- 设值点：`designs.importImageBytes({ name, base64, source })` 把 `source` 写进原件 metadata；`asset-library.upsert(asset, metadata)` 把 `metadata.source` 落到条目上（弹窗/清理都能读）。
- 模板上传：`source: 'template'`；底图制作导入：`source: 'library'`。
- 向后兼容：M1 既有素材库原件无 `source` 字段 → 默认按 `'library'`（受管理），绝不误删。

### 2.2 三处分流点

**（A）`templates.discardBackground(assetId)` 与 `templates.deleteTemplate` 连带清理**
- 先算「还有没有任何模板 / 工程引用它」（复用扩展后的 `referencedAssetIds()`）。
- `source === 'template'` 且**已无引用** → 立刻删原件（`design-assets/<hash>.{png,jpg,json}` + 缩略图），保留现在的即时删除手感。
- `source === 'library'`（或已归档）→ 只撤引用，**留文件**（I-31③）。
- 仍走 dataDir 越界守卫，绝不删到目录外。
- 生命周期归属：在 `asset-library` 加 `discardIfEphemeral(assetId)`（或 `releaseTemplateBackground`），由它做分支决策；`templates.cjs` 仅调用，不自己删文件。保持 I-31「原件生死归素材库」的单一权威。

**（B）`asset-library.referencedAssetIds()`（扫描指针接过来）**
- 现在只扫「素材库索引 + 各工程图层」，需**补扫所有模板的 `background`（assetId）**。
- 否则模板底图会被「清理未引用」误杀。
- `asset-library` 引入 `templates.cjs` 安全（链路 `asset-library → templates → render-engine → designs`，不回指 `asset-library`，无循环依赖）。建议新增 `templates.listBackgroundAssetIds()` 供扫描。

**（C）孤儿清理「清理未引用」（`findOrphanOriginals` / `purgeOrphanOriginals`）**
- `source === 'template'` 的孤儿（如模板被直接删、没走 discard）→ 本就该回收，清理时直接删。
- `source === 'library'` 的孤儿 → 只在用户**显式确认**后才删（现有确认弹窗已覆盖，符合「不立刻释放磁盘」）。

### 2.3 去重升级单向规则（锁死）

同一张图：先从模板页传（`source: 'template'`），后用户从底图制作「加入素材库」（`adopt` → `source: 'library'`）。因内容寻址共用一个 `assetId`，`source` 只能 **template → library 单向升级，绝不回退**。即：一旦进过素材库，就变受管理、不再即时删。正好对应「从底图制作导进入素材库的才不是立刻删除」。

## 3. 渲染解析改动（唯一非 UI 的前端改动，不是新按钮）

- `TemplateView.vue:367` 的 `pp://media/${activeTpl.value.background}` → 改 asset 感知，返回 `pp://media/design-assets/<sha256>.png`（`pp://` 协议按 rel 直接映射 dataDir，无需改协议处理器）。
- `render-engine.cjs:302` 的 `inlineUrl(template.background)` → 加按 assetId 读 `design-assets/<hash>` 的解析（同 `design-layout.cjs:188` 读 `asset.path` 写法）。
- 兼容期：`bgUrl` / `inlineUrl` 同时能解析旧 `print-bg/...` 路径与新 `asset_<sha256>`，首次加载把旧路径惰性迁成 asset（见 §4）。

## 4. 契约变更与迁移

`template.background` 形状变了（路径 → assetId），属序列化契约变更：

- **种子模板 / 存量用户模板**：存量 `print-bg/...` 背景走「双形态解析 + 首次加载惰性迁移」——读时若仍是 `print-bg/` 路径，哈希该文件 → `importImageBytes` → 把 `background` 替换为 `assetId`（并标 `source: 'template'`）。池子最终完全统一。
- **静态守卫**：`docs/不变量契约.md` 加 I-33（模板底图须走素材库原件、不得存 `print-bg/` 路径副本；`discard` 对 `source:'library'` 不得删原件）。登记进 `test/invariants.cjs` 的 `CONTRACT`（钉源码文本）。
- **旧 `print-bg/` 目录**：迁移期保留只读兜底；全部迁完后废弃（不主动删用户目录，留待后续清理）。

## 5. 测试点（落地时补全）

- 模板上传底图 → `template.background` 为 `asset_<sha256>`，原件落在 `design-assets/`，`asset-library.json` 有 `source:'template'` 条目。
- 模板 discard 底图（`source:'template'`、无他引）→ 原件被删；`source:'library'` → 原件保留。
- `referencedAssetIds()` 含模板背景 → 「清理未引用」不误杀在用模板底图。
- 去重升级：`template` 上传同图后再 `adopt` 为 library → `source` 升 `library`，不再即时删。
- 存量 `print-bg/` 背景加载 → 惰性迁为 asset，渲染正常。
- 渲染：canvas 预览（`pp://media/design-assets/...`）与 PDF/PNG 导出（`inlineUrl(assetId)`）均正确嵌图。

---

## 6. 语义变化（已与用户确认）

- **去重生效**：同一张抬头/logo 在多个模板复用 → 只存一份原件（之前 `print-bg/` 是 1:1 副本）。
- **`source:'library'` 底图「移除」不再立刻释放磁盘**：仅撤引用，文件等「归档 + 孤儿清理」才回收——更安全，但和旧「换图即删文件」不同，属预期行为。
- **`source:'template'` 底图「移除」保留现在的即时删除手感**。
