# 后台重复素材自动管理方案

## 目标

每次启动应用时，在后台盘点素材和可再生缓存，自动回收能够证明无业务用途的数据，释放空间；不要求用户逐条处理。界面保留整理结果、实际释放量及异常信息，允许用户查看和控制自动整理。

用户已明确：**主动导入素材库的素材，即使未收藏、未用于工程，也要保留**。收藏素材、已保存工程、模板和打印项目涉及的内容同样保留。名单中已导入或绑定的照片、已应用的照片处理结果和单人修改虽可能尚未打印，也是现有工作的一部分，必须保护，否则下次打开名单或打印时会缺图。

本方案不扫描用户任意目录；文件名相同、视觉相似或文件大小相近都不足以证明内容相同。不同压缩、尺寸、元数据和编辑版本不自动合并。

## 当前基础与限制

- 素材按原始字节 SHA-256 寻址；多个名单或工程共享同一 `assetId` 是正常复用，不等于多个文件。
- `design-assets`、`ephemeral-assets` 和 `photo-assets` 是不同存储池。照片与设计素材会有意分别保存同 hash 的副本，素材库目录还可能位于独立磁盘。跨池同 hash 不能直接视为无用。
- `asset-library.cjs` 已有引用扫描和孤儿清理，但 `purgeOrphanOriginals` 会按 hash 横跨所有池删除，不能用于删除仍被引用素材的一份跨池副本。现有 I-32 要求孤儿清理显式确认；要实现自动删除原件，必须先明确修改该契约并补充对应测试，不能绕过现有保护。
- 打印归档维护独立快照和照片副本，用于回看和迁移；处理缓存、缩略图、导入暂存也各有生命周期。不能用同一种删除规则处理所有目录。

## 保留与回收规则

| 对象 | 默认决策 | 判断依据 |
| --- | --- | --- |
| 素材库中用户主动导入或加入的素材，含收藏与归档 | 保留 | 用户有意保存，不能只看是否收藏或是否使用 |
| 已保存工程、模板及其固定历史版本、单人底图版本 | 保留 | 完整引用链，包括引用的素材和依赖 |
| 名单照片绑定、单人照片修改及当前生效处理结果 | 保留 | 名单即使尚未打印也可能继续使用；包括原图、处理图和恢复图 |
| 已打印或已导出项目的历史快照 | 保留 | 保证历史回看、补打和归档迁移；按实际任务定义核实 |
| 正在进行或待恢复的导入、处理任务及草稿 | 保留 | 日志、未提交的数据和运行中的引用均不能按孤儿处理 |
| 失效缩略图和明确可重新生成的缓存 | 自动回收候选 | 需逐类证明重建路径，清理后仍能使用且不丢失用户编辑 |
| 已结束任务的无效暂存、确认失效的迁移残留 | 自动回收候选 | 任务日志和恢复状态完整，目标路径及文件身份均经校验 |
| 不属于上述保留范围、完整扫描后确认无引用的原件 | 自动回收候选 | 需通过下述保护期、复核和可恢复流程；若来源或引用未知则保留 |
| 跨池同内容副本 | 默认保留 | 只有逐类证明删除某个池副本不影响读取、备份和生命周期，才能在未来启用特定规则 |
| 损坏、目录不可达、文件变动或引用无法确认 | 跳过并报告 | 不把未知当成未使用 |

现有素材库索引是受保护的，即使未收藏也保留；自动清理不改变条目、标签、名称或归档状态。原始照片、手工修改结果和用户主动导入的素材不是可再生缓存。

## 启动时执行流程

1. **完成恢复与准备。** 先取得现有数据目录锁，完成数据目录选择、迁移及未完成事务恢复，并确认索引、素材池与外置目录可访问。不能获得独占协调、存在未恢复任务或关键数据损坏时，跳过清理并记录原因。
2. **后台扫描。** 主窗口可先显示；工作线程或分片任务低优先级扫描，限制并发与内存，避免影响启动和用户操作。识别逻辑引用、逐池物理文件、来源和已知用途；对跨池候选流式重算内容哈希，不能仅相信文件名。
3. **建立候选。** 对每份候选记录类型、原因、文件身份、字节数、引用扫描版本及首次发现时间。候选必须经过两次不同启动的完整扫描，并至少经过 7 天观察期（初始建议值），期间任何引用、任务或文件状态变化都重置观察期。缓存类如果已有可证明安全的独立生命周期，可另行制定规则，不能沿用原件规则。
4. **执行前复核。** 在与导入、编辑保存、打印和照片处理共用的协调机制下重新检查引用、草稿保护、任务状态、文件身份和 hash；候选发生变化、出现引用或验证失败就跳过。仅持有进程级数据锁不足以排除本进程内并发写入，需实现明确的任务协调或提交前互斥。
5. **可恢复回收。** 对允许自动回收的原件，先写事务日志并移入同一文件系统内的受控回收区；跨卷时使用校验后的复制、同步和删除流程，不能假设重命名原子。回收区保留至少 30 天（初始建议值），支持恢复，期间容量单独展示；到期后再次核对保护和日志，再删除并报告实际释放的字节。仅移动到回收区不算已释放空间。
6. **结果展示。** 提供最近整理时间、已删除/隔离/恢复/跳过/失败数量及实际释放空间；提供暂停或关闭自动整理、查看原因和恢复入口。重启后按事务日志恢复一致状态，重复执行不重复计数。

上述时间为设计参数，实施前需结合实际存储压力验证。用户在扫描期间开始编辑或导入时，相关候选应暂停或跳过；无法获得实时草稿保护时不得清理可能涉及草稿的原件。

## 引用盘点与空间统计

实现只读引用明细，至少覆盖现有 `referencedAssetIds` 的保护范围：素材库（含归档）、名单绑定和照片例外、照片处理缓存及活动结果、当前工程、模板所固定的历史工程版本、单人底图版本、导入暂存日志，以及进行中的工作和草稿。新增覆盖打印归档的明确审计，并以现有真实文件结构验证；关键索引缺失、损坏或无法读取时，停止相关范围的原件清理并显示原因。

空间总览分开显示原件物理占用、跨池相同内容的理论重复字节、未引用候选、回收区、历史快照、缓存与暂存。分类可能重叠，不能简单相加；理论重复字节不等于可释放空间。每次整理仅按成功删除的实际文件字节计入释放量，保留失败及跳过原因。对文件和路径做池内校验，不跟随符号链接，也不接受前端传入任意删除路径。

## 分期实施

1. **引用盘点与模拟运行。** 三池逐文件清单、哈希校验、引用明细、完整性检查和启动后台扫描；输出拟自动回收清单和原因，暂不删除。用真实数据验证遗漏、误判和性能。
2. **自动回收明确可再生的缓存和已结束任务残留。** 按类型独立验证重建、失败恢复和并发保护，接入结果统计。
3. **自动回收已确认的无引用原件。** 更新 I-32 契约后，加入观察期、隔离、恢复、事务日志与删除前复核；验证全部保护范围后启用。这个阶段才自动处理过去需要显式确认的孤儿原件。
4. **跨池副本优化。** 单独验证池隔离、路径解析和独立备份约束，只有在具体场景证明不影响使用时才增加自动规则；历史快照仍独立评估。

当前进度：已接入启动后后台文件检查、跨池哈希核验、边车异常提示及素材库内分页报告；报告列出素材库、名单照片、照片处理、工程当前版本、模板固定版本、单人底图和导入任务中的已知引用，并核验打印历史中独立保存的照片副本。损坏或变化的索引只报告，不由扫描器写入修复。尚未核实所有未保存草稿、历史快照内嵌图片及引用来源，也未生成可自动回收原件的候选或启用原件自动清理，因此不能用当前报告判断哪些原件可以清理。

已启用的自动删除仅限旧缩略图缓存：应用成功持有数据目录锁、素材库索引可读且不含该素材、缓存至少 7 天未更新，且存在经 SHA-256 校验的原件时，删除前重新核对索引、原件与缓存的文件状态，满足条件才删除缓存。归档素材库条目同样受保护；缺失原件、索引损坏及文件变动均跳过。结果在「重复素材检查」中报告，本次运行的实际释放量只计成功删除的缓存。原件、归档和照片处理结果的自动删除尚未启用。

## 验收重点

- 未收藏但主动导入的素材、归档和收藏均保留；工程、模板固定版本、未打印名单照片、处理结果、单人修改和历史打印项目持续可用。
- 两次扫描间新增引用、导入/保存/打印并发、应用中断、回收区恢复与删除失败均不丢图；重复启动与事务恢复可重入。
- 索引损坏、照片任务日志缺失、外置目录断开、hash 不符、路径越界或符号链接导致对应范围跳过；不会报告为成功清理。
- 同 hash 跨池副本保持各池语义；视觉相似但内容不同不会合并；保留副本无法读取时不删除其他副本。
- 模拟运行零写入业务数据；回收区占用和真实释放字节统计准确；大批素材扫描不阻塞使用，可暂停并查看结果。
