# 「印」开关：点亮字段的完整口径

> 数据集里每一列都有一个「印」开关（`printOn`）。它决定这一列能不能被模板使用。
> 这一节把它控制什么、不控制什么、谁负责点亮、怎么校验写全 —— 因为这几点很容易被想当然地搞反。

## 一句话

**「印」开关不是出片闸门，是绑定的前提。**

已配置好的模板直接出片时，渲染读的是行里的值，不看开关；但要在模板里**选中**这一列、或者把模板**换绑**到这份数据集，就必须是亮的。

## 它控制的三件事

| 场景 | 行为 | 代码位置 |
|---|---|---|
| 模板编辑页的字段选择器 | 只列出 `printOn === true` 的列 | `src/views/TemplateView.vue` |
| 换绑 / 新建模板时的匹配校验 | 模板已放置的字段若未激活，判定「结构错配」，拒绝绑定 | `electron/templates.cjs` 的 `matchFields` |
| 打印预检 | 未激活的列被报成 `missing`，提示去数据页点「印」 | `electron/print.cjs` 的预检 |

## 它不控制的一件事（最容易搞错）

**不影响已配好模板的出片。** 渲染取 `ds.rows[ri][colName]`，值存在就印，不查开关。

这条是靠实测校准的，不是读注释得出的：某单位的数据集**全部字段都未点亮**，当天照样重出 4 张且内容全部正确。注意这条与「几个字段」无关——不管清单是 5 个还是 9 个，开关都不参与已配好模板的渲染。

而 `electron/print.cjs` 里那段注释写的是「否则模板照常出片，字段位置印出来是空白」——读起来像是开关关掉就会空白。**注释写的是设计意图，不是当前行为。** 遇到这类冲突，以实测为准，然后把实测结论写下来。

## 谁负责点亮

`import` 导入名册后，逐列点亮字段。要点亮哪些列，**以模板为准**：批处理工具把模板 `fields[].column` 与实际配置的 `requiredFields` 取并集，生成最终的必填清单（见 `tools/ppw/config.cjs` 的 `mergeRequiredFields`）。所以字段数量是跟着模板变的——模板这次 5 个字段就点亮 5 个，改成 9 个就点亮 9 个，不需要有人记得同步第二份名单。

正确性依赖两件事：

1. 模板 `fields[].column` 里声明的列，在数据集里**存在**——不存在就会直接空白，值无从取
2. 配置里的匹配规则能把这些列从源表头**认出来**（`eq:` 精确 / `prefix:` 前缀 / `contains:` 包含）

第 2 条是现在的脆点，而且已经被 `matchHeader` 收窄过一次：**先找完全同名表头，命中即返回**，只有找不到同名时才退回 `prefix` / `contains`。原因是表头里常有一对长得很像的兄弟列，`contains:奖项` 会抢到排在前面的「实际奖项」，让真正要渲染的那列从头到尾没被读过。

所以新增字段时，默认只需要改模板——清单自动跟上。只有一种情况要手工补配置：数据集列名与源表头**写法不一致**（例如列名是 `所在学校必须写全名`，源表头写的是 `所在学校（必须写全名）＊`）。这时默认的「精确同名」认不出来，需要在 `requiredFields` 里加一条 `prefix:所在学校`；认不出来的表现是这一列永远取到空值，而不是报错。

## 怎么校验

```bash
node tools/ppw.cjs verify              # 全部单位
node tools/ppw.cjs verify --unit 55    # 单个单位
```

它做三件事：

1. **读模板** `fields[].column`，得到模板真正要渲染的字段集合
2. **对比必填清单**，找出「模板要但清单没有」的列（正常情况下为空——清单本就由模板推导，有差异说明配置或模板没读到）
3. **逐单位检查出片时实际会取到的那份数据集**（按 `pickDataset` 口径，不是随便挑一份）的列存在性与开关状态

判定分级：

| 情况 | 级别 | 后果 |
|---|---|---|
| 模板要的列在数据集里**不存在** | error | 出片该位置必然空白 |
| 列在但**未点亮** | warn | 不影响已配好的模板出片；影响改模板、换绑、预检 |
| 模板要的列**不在必填清单** | warn | 新导入的单位不会点亮它，将来踩上一条 |
| 必填但模板不渲染 | info | 多校验一次，无影响 |

退出码只在有 error 时为 1。

## 什么时候必须跑

- **新导入一批名册之后**——确认配置清单与模板字段没有脱节
- **改过模板字段之后**——清单会自动跟上，但仍要确认这次导入的数据集已把新列点亮
- **换绑数据集之前**
- 出片后发现某个位置空白，第一个要怀疑的就是这里

改模板字段后不必重出全部成品：已配好的模板出片不受开关影响，只需要补点亮，让后续编辑可用。

## 补点亮的两种办法

```bash
# 逐列打开（需要连宿主）
# 或重新 import 这份名册 —— 会按 requiredFields 重新点亮
node tools/ppw.cjs import --roster 合并_1-60号.xlsx
```

注意 `import` 默认拒绝重复导入（防止同名副本），已有数据集时需 `--force`；更稳妥的做法是逐列 `pp_dataset_setColumnPrint`。

## 附带发现：同一单位可能有多份数据集

校验时会顺带报出「有重份的组」。本批次实测 231 个单位对应 266 份数据集，35 组有重复。

出片按 `pickDataset` 取：优先名字以 `合并_` 开头的，否则取最后一份。**取哪份是有规则的，但也意味着过时的那份可能被静默选中。** 重复导入产生的同名副本就是这个后果，所以 `import` 才在检测到同前缀时直接拒绝。
